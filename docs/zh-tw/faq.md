# 常見問題

## 一般問題

### 什麼是 FEE？

FEE（Frontend Engineering Essentials，前端工程精要）是一組編號化的前端工程指南。完整概覽請參見 [FEE-0](0)。

### FEE 的目標讀者是誰？

所有層級的前端工程師──從學習基礎的新手到深化架構能力的資深工程師。FEE 建立概念基礎，而非特定廠商的教學。

### FEE 是否針對特定框架？

不是。FEE 的原則與廠商和框架無關。當某個概念最適合用特定技術來說明時，會明確標註為範例而非推薦。

### FEE 與 BEE、ADE、DEE 的關係是什麼？

FEE 廣泛涵蓋前端工程。BEE（後端工程精要）涵蓋後端。ADE（API 設計精要）深入 API 設計。DEE（資料庫工程精要）深入資料庫設計。它們在主題重疊處互相交叉引用。

### 我可以提出新的 FEE 嗎？

可以。請遵循 [FEE-0](0) 中描述的結構，並提交 pull request。

## 內容問題

### 為什麼使用 RFC 2119 關鍵字（MUST、SHOULD、MAY）？

這些關鍵字提供精確的指引層級。MUST 表示該原則不可違反。SHOULD 表示除非有明確記錄的理由否則應遵循。MAY 表示可選。

### FEE 編號如何分配？

FEE 按類別範圍編號，每個類別 100 個編號。完整對照請參見 [FEE-0](0) 的類別表。

### 如果我的情況需要偏離某個 FEE 怎麼辦？

記錄原因。FEE 是指南，不是法律。目標是做出有根據的決策，而不是盲目遵守規則。
