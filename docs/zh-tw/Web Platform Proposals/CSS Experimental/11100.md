# [FEE-11100] Scroll-driven Animations — 捲動驅動動畫

:::info
完全用 CSS 實現捲動連動動畫——進度條、視差、淡入效果——零 JavaScript、零主執行緒成本。
:::

:::info Baseline Newly Available
Chrome 115+、Edge 115+、Safari 18+ 已支援。Firefox 截至 2026 年 4 月仍需開啟旗標（`layout.css.scroll-driven-animations.enabled`），預設未啟用。正式使用前請至 MDN 確認最新 Firefox 支援狀態。
:::

## 背景

捲動連動效果一直是現代 UI 的常見需求：文章頂端的閱讀進度條、元素進入視口時的淡入效果、隨頁面捲動改變樣式的固定導覽列。這些效果過去全都需要 JavaScript。

典型的做法是結合 `scroll` 事件監聽器與 `requestAnimationFrame`：

```js
window.addEventListener('scroll', () => {
  requestAnimationFrame(() => {
    const progress = window.scrollY / (document.body.scrollHeight - window.innerHeight);
    progressBar.style.transform = `scaleX(${progress})`;
  });
});
```

這個做法有一個根本缺陷：`scroll` 事件在主執行緒上觸發。如果主執行緒正在執行耗時任務——解析腳本、處理 React 重新渲染、處理大型資料集——捲動處理函式就會被延遲執行。使用者捲動頁面，進度條卻沒有跟著移動，造成明顯的卡頓感。

`IntersectionObserver` 改善了元素進入或離開視口的偵測，但無法表達基於進度的動畫。元素不是「正在交叉」就是「沒有交叉」，不存在「進入視口 30%」的回呼。

第三方函式庫填補了這個空缺。GSAP ScrollTrigger 和 Locomotive Scroll 提供了成熟可靠的捲動動畫 API。它們透過 `requestAnimationFrame` 迴圈與 `will-change` 提示來降低卡頓，但觸發邏輯——計算當前進度並套用 CSS 的部分——仍然在主執行緒上執行，同時也為每個使用的頁面增加了額外的 JavaScript 體積。

CSS 捲動驅動動畫將所有這些工作移到瀏覽器的合成器執行緒（compositor thread）。瀏覽器在解析階段就建立捲動容器與動畫之間的關聯，捲動時由合成器執行緒——負責處理所有合成 `transform` 和 `opacity` 動畫的低階元件——直接讀取捲動位置並推進動畫，完全不需要通知主執行緒。

## 情境

你正在開發一個長篇文章頁面，需要兩種效果：

1. 固定在視口頂端的閱讀進度條，從左到右隨使用者從頁首捲動到頁尾而填滿。
2. 一系列內容卡片，每張卡片捲入視口時從下方淡入。

傳統做法需要兩個 `scroll` 事件監聽器、兩個 `requestAnimationFrame` 迴圈，以及至少 30–50 行 JavaScript。使用 CSS 捲動驅動動畫，兩種效果都可以完全在 CSS 中宣告式地實現。

## 最佳實踐

- MUST 將所有捲動驅動動畫規則包裹在 `@media (prefers-reduced-motion: no-preference)` 中。會移動元素、改變透明度或影響佈局的捲動驅動動畫，可能在敏感使用者身上觸發前庭功能障礙（vestibular disorders）。這個包裹層不可省略。
- SHOULD 優先在捲動驅動的 `@keyframes` 中只對 `transform` 和 `opacity` 設定動畫。這兩個屬性屬於合成器可處理的屬性（compositor-eligible）——不觸發佈局或繪製，可在合成器執行緒上獨立執行。
- MUST NOT 對 `top`、`left`、`width`、`height`、`margin`、`padding` 或任何會觸發佈局重新計算的屬性設定動畫。這樣做會在每次捲動時強迫瀏覽器執行佈局，完全抵消移至 CSS 帶來的效能優勢。
- SHOULD 使用 `animation-timeline: view()` 實現「元素進入視口時播放動畫」的效果。
- SHOULD 使用 `animation-timeline: scroll()` 實現全頁進度指示器（閱讀進度條、視差背景）。
- 若該效果對佈局而非純裝飾至關重要，SHOULD 搭配 `@supports (animation-timeline: view())` 進行漸進增強。
- 使用 `view()` 時間軸時，SHOULD 設定 `animation-fill-mode: both`，以保留元素離開視口後的最終關鍵影格狀態。

## 設計思維

### 為什麼 JS 捲動監聽器會造成卡頓

JavaScript 事件處理函式——包括 `scroll`——在瀏覽器的主執行緒上觸發。主執行緒同時負責解析 HTML 和 JavaScript、執行框架程式碼、處理使用者輸入以及執行計時器。在繁忙的頁面上，主執行緒可能一次被佔用數十甚至數百毫秒。

當 `scroll` 事件觸發時，若主執行緒正在忙碌，事件會排隊等待。等到處理函式真正執行時，使用者已經捲動得更遠了。動畫必須跳躍式地追趕，產生使用者明顯感受到的卡頓。`requestAnimationFrame` 透過將更新批次到下一次繪製前來減少這種情況，但仍然需要等待主執行緒空閒。

### GSAP ScrollTrigger 如何解決這個問題

GSAP ScrollTrigger 將捲動監聽器包裹在 `requestAnimationFrame` 迴圈中，並對即將產生動畫的元素添加 `will-change: transform` 提示。這告訴瀏覽器將這些元素提升到獨立的合成器層，讓 GPU 處理其 `transform` 變換。效果比原始的捲動監聽器流暢得多，但決定當前進度並套用 CSS 的觸發邏輯，仍然在主執行緒上執行。

### 為什麼 CSS 原生方案更優

CSS 捲動驅動動畫在捲動過程中完全不執行 JavaScript。瀏覽器在解析階段就登記捲動容器與動畫之間的關係。捲動時，合成器執行緒——負責所有合成 `transform` 和 `opacity` 更新的元件——直接讀取捲動位置並推進動畫，從不通知主執行緒。

這意味著：

- 一個阻塞主執行緒 200 毫秒的 JavaScript 任務，不會影響 CSS 捲動驅動動畫。在整個阻塞期間，動畫仍然以正確的捲動位置繼續運行。
- 不需要維護任何 `requestAnimationFrame` 迴圈，沒有元件卸載時的清理工作，也沒有監聽器洩漏的風險。
- 此功能會靜默降級：不支援 `animation-timeline` 的瀏覽器會直接以元素的預設狀態顯示，彷彿從未套用過 `@keyframes`。

## 範例

以下兩個範例都包裹在同一個 `@media (prefers-reduced-motion: no-preference)` 區塊中，符合最佳實踐要求。

### 範例一：使用 `scroll()` 的閱讀進度條

```html
<div class="progress-bar"></div>
<article class="content">
  <!-- 長篇文章內容 -->
</article>
```

```css
.progress-bar {
  position: fixed;
  top: 0;
  left: 0;
  width: 100%;
  height: 4px;
  background: #e2e8f0;
  z-index: 100;
  transform-origin: left;
}

@media (prefers-reduced-motion: no-preference) {
  @keyframes grow-progress {
    from { transform: scaleX(0); }
    to   { transform: scaleX(1); }
  }

  .progress-bar {
    animation: grow-progress linear;
    animation-timeline: scroll(root block);
    /* root = 文件根捲動容器，block = 垂直軸 */
  }
}
```

`scroll(root block)` 將動畫連結至根捲動容器（整份文件）的 block（垂直）軸。使用者從頁面最頂端捲動到最底端的過程中，`grow-progress` 從 `scaleX(0)` 執行到 `scaleX(1)`，將進度條填滿。

省略引數——`scroll()`——會使用最近的可捲動祖先元素和 block 軸。對於全頁進度指示器，務必明確指定 `root`，無論 DOM 巢狀結構如何，都能確保使用正確的捲動容器。

### 範例二：使用 `view()` 的卡片淡入效果

```html
<section class="cards">
  <div class="card">卡片一</div>
  <div class="card">卡片二</div>
  <div class="card">卡片三</div>
</section>
```

```css
.card {
  /* 動畫播放前的基底狀態 */
  opacity: 1;
  transform: translateY(0);
  background: #fff;
  padding: 2rem;
  margin-block-end: 2rem;
  border-radius: 8px;
  box-shadow: 0 2px 8px rgb(0 0 0 / 0.1);
}

@media (prefers-reduced-motion: no-preference) {
  @keyframes fade-up {
    from {
      opacity: 0;
      transform: translateY(40px);
    }
    to {
      opacity: 1;
      transform: translateY(0);
    }
  }

  .card {
    animation: fade-up ease-out both;
    animation-timeline: view();
    /* 在元素進入階段的前 40% 內播放完整動畫 */
    animation-range: entry 0% entry 40%;
  }
}
```

`view()` 將動畫連結至元素本身在捲動容器中的可見度。`animation-range: entry 0% entry 40%` 告訴瀏覽器：從元素開始進入視口的瞬間，到它進入 40% 的位置，播放完整的 `fade-up` 關鍵影格序列。`animation` 簡寫中的 `both` 填充模式，在進入前保持 `opacity: 0`，在離開後保持 `opacity: 1`。

## 深入探討

### 具名捲動時間軸

匿名的 `scroll()` 和 `view()` 函式適用於動畫元素是捲動容器後代的情況。當元素不是捲動容器的後代——例如，一個需要與特定捲動區域同步的固定側邊欄——就需要使用具名時間軸：

```css
/* 在捲動容器上宣告 */
.scroll-region {
  scroll-timeline-name: --region-timeline;
  scroll-timeline-axis: block;
  /* 簡寫：scroll-timeline: --region-timeline block; */
  overflow-y: scroll;
}

/* 任何元素都可以引用該容器的捲動時間軸，無論是否為其後代 */
.sidebar-indicator {
  animation: track-scroll linear both;
  animation-timeline: --region-timeline;
}

@keyframes track-scroll {
  from { transform: scaleY(0); }
  to   { transform: scaleY(1); }
}
```

`scroll-timeline-name` 屬性將容器宣告為具名捲動時間軸來源。任何元素——無論是否為後代——都可以透過 `animation-timeline: --region-timeline` 引用該名稱。

### `@scroll-timeline` 規則集（歷史背景）

規範早期草案中使用 `@scroll-timeline` 規則集來宣告具名時間軸。這個語法出現在非常早期的 Chromium 原型（Chrome 115 之前）和 2021–2022 年的文件中。在功能進入穩定版本之前，已被 `scroll-timeline-name` 和 `scroll-timeline-axis` 屬性所取代。如果你在舊版教學或函式庫中看到 `@scroll-timeline`，請將其視為已過時的語法——任何現代瀏覽器均未實作，也不屬於現行規範。

### `animation-fill-mode: both` 與 view 時間軸

使用 `view()` 時，元素的動畫在捲動時間軸中有明確的起點和終點。元素完全離開視口後，動畫便超出其有效範圍。若未設定 `animation-fill-mode`，元素會還原到初始 CSS 狀態（這可能意味著元素在捲過後又以 `opacity: 0` 重新出現）。設定 `animation-fill-mode: both`（或在 `animation` 簡寫中使用 `both`）可在有效範圍結束後保留最終的關鍵影格數值。

### View 時間軸的各個階段

`animation-range` 屬性接受具名的階段關鍵字，對應元素在捲動容器中移動路徑的各個幾何區域：

| 階段       | 說明 |
|----------|------|
| `entry`  | 元素部分可見且正在進入視口（前緣已越過捲動視口的遠端邊界，後緣尚未越過） |
| `contain`| 元素完全位於捲動視口內（兩端均可見）——僅在元素比捲動視口短時適用 |
| `exit`   | 元素部分可見且正在離開視口 |
| `cover`  | 從元素前緣首次出現到後緣消失的整段過程——完整的可見弧線 |

混合使用多個階段是合法的：`animation-range: entry 50% exit 50%` 從進入階段的中點開始動畫，在離開階段的中點結束。

### 匿名時間軸與具名時間軸的比較

| | 匿名時間軸 | 具名時間軸 |
|---|---|---|
| 語法 | `scroll()` / `view()` | `scroll-timeline-name` + `animation-timeline: --name` |
| 捲動容器 | 最近的可捲動祖先（或 `root`） | 任意具名容器，包含非祖先元素 |
| 適用情境 | 單一元素與其祖先捲動時同步動畫 | 協調多個元素與特定捲動容器同步 |
| 程式碼量 | 最少 | 需在容器上宣告，並在動畫元素上引用 |

大多數捲動連動效果使用匿名時間軸更簡潔清晰。當動畫元素不是捲動容器的後代，或多個不相關的元素需要與同一捲動區域同步動畫時，才需要具名時間軸。

### 漸進增強模式

```css
/* 預設：無動畫，元素以最終可見狀態呈現 */
.card {
  opacity: 1;
  transform: none;
}

/* 增強：在支援的瀏覽器中啟用捲動動畫 */
@supports (animation-timeline: view()) {
  @media (prefers-reduced-motion: no-preference) {
    .card {
      animation: fade-up ease-out both;
      animation-timeline: view();
      animation-range: entry 0% entry 40%;
    }
  }
}
```

將基底狀態設為 `opacity: 1`，確保 Firefox（功能在旗標後）或舊版瀏覽器的使用者仍能正常看到所有內容。

### 在同一頁面混用 `scroll()` 與 `view()`

在同一頁面同時使用兩種類型的時間軸不會產生衝突。閱讀進度條可以使用 `animation-timeline: scroll(root block)`，同時各個卡片使用 `animation-timeline: view()`。每個動畫元素各自獨立引用自己的時間軸來源，彼此互不干擾。

對同一個元素套用多個動畫，每個動畫使用不同的時間軸也是合法的，只要 `animation-timeline` 列表中的項目與 `animation-name` 列表中的項目一一對應即可：

```css
.hero-image {
  animation: fade-in ease-out both, parallax-shift linear both;
  animation-timeline: view(), scroll(root block);
  animation-range: entry 0% entry 60%, normal;
}
```

在這個範例中，`fade-in` 使用元素本身的 `view()` 時間軸，而 `parallax-shift` 使用根捲動進度。第二個動畫的 `animation-range: normal` 代表從 0% 到 100% 的完整捲動範圍。

## 瀏覽器支援

| 瀏覽器 | 首次支援版本 | 備註 |
|--------|------------|------|
| Chrome  | 115        | 完整支援——`scroll()`、`view()`、`animation-range`、具名時間軸 |
| Edge    | 115        | 基於 Chromium，與 Chrome 相同 |
| Safari  | 18         | 於 Safari 18（2024 年 9 月）加入完整支援 |
| Firefox | —          | 截至 2026 年 4 月，需開啟 `layout.css.scroll-driven-animations.enabled` 旗標；預設未啟用——請至 MDN 確認最新狀態 |

漸進增強檢測：

```css
@supports (animation-timeline: view()) {
  /* 捲動驅動動畫樣式 */
}
```

或在 JavaScript 中進行功能偵測：

```js
const supported = CSS.supports('animation-timeline', 'view()');
```

由於 Firefox 預設未啟用此功能，正式環境使用時應將捲動驅動動畫視為純粹的漸進增強（裝飾性效果，具備優雅的降級），或搭配 `@supports` 守衛與 JavaScript 降級方案，為不支援的瀏覽器提供備援。

## 內部參考

- [FEE-11101 @starting-style](../Animation%20and%20Scroll-Linked%20Effects/11101.md) — 互補功能：`@starting-style` 處理元素的*進入*過渡效果（首次渲染），而捲動驅動動畫處理捲動時間軸上的進度動畫。兩者結合可讓卡片在初始渲染時播放入場動畫，並在捲動觸發時再次播放。
- [FEE-11001 CSS Anchor Positioning](./11001.md) — 兩者都是取代 JavaScript 驅動定位與動畫的新一代功能。CSS Anchor Positioning 移除了 JS 測量的需求；捲動驅動動畫移除了 JS 捲動監聽器。
