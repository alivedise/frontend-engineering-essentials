# [FEE-11003] CSS Subgrid — 子網格

:::info
CSS Subgrid 讓巢狀網格元素得以參與父層網格的軌道尺寸計算，使同列卡片的內部列與欄能對齊至相同軌道——不需要 JavaScript、固定高度或 margin 技巧。
:::

:::tip Baseline
This feature is Baseline Widely Available. Supported in Chrome 117+, Firefox 71+, Safari 16+.
:::

## 背景

CSS Grid Level 1 引入了強大的二維版面配置系統，但有一項刻意的限制：網格軌道只存在於宣告它們的元素上。放置在網格格子中的子元素，會成為一個新的獨立版面配置上下文。其自身的子元素——也就是原始網格的孫元素——無法參與祖父元素的軌道。每一層巢狀都定義了自己的獨立網格。

這個限制在卡片式版面配置中最為明顯。以三欄商品網格為例：每張卡片包含一張圖片、一個標題、一段描述，以及一個行動按鈕。某張卡片的標題可能只有一行，另一張可能有兩行；某張卡片的描述很短，另一張可能有四行。由於每張卡片是獨立的網格（或 flex）容器，「立即購買」按鈕在每一欄的垂直位置都不同。視覺韻律被破壞了。

在 subgrid 出現之前，工程師嘗試過許多變通方案，但沒有一種是優雅的：

1. **Flexbox 欄排列搭配 `margin-top: auto`** — 對卡片設定 `display: flex; flex-direction: column`，對按鈕設定 `margin-top: auto`。這能將按鈕推到卡片底部邊緣，但無法讓按鈕在同列兄弟卡片間對齊至同一基準線——若各卡片總高度不同，一張卡片的底部與另一張的底部也在不同位置。
2. **對各區塊設定固定 `min-height`** — 為標題、描述和圖片區域設定固定最小高度，確保無論內容長短都佔用相同的垂直空間。這很脆弱：一旦內容變更（更長的商品名稱、翻譯後的文字、更大的圖片），版面就會悄悄地壞掉。
3. **JavaScript 量測** — 使用 `ResizeObserver` 或一次性量測腳本讀取每列中最高的元素，再將該高度套用到所有兄弟元素。雖然有效，但在版面正確顯示之前需要先執行 JavaScript，且會造成第二次版面計算，每次視窗大小改變時都必須重新執行。
4. **CSS Grid 搭配 `align-items: stretch`** — 拉伸對齊所有卡片使其與最高的兄弟等高，再在內部使用絕對定位或 flex。仍然無法讓不同卡片的內部列對齊至相同基準線。

CSS Grid Level 2 引入 `subgrid` 值，在規格層面解決了這個問題。子網格元素選擇參與父層的軌道，而非自行定義，讓宣告式的跨兄弟元素對齊成為可能——不需要 JavaScript，也不需要任何魔法數值。

## 情境

你正在建立一個商品列表頁面。設計要求是三欄的卡片網格。每張卡片有四個不同的區塊，必須在三欄之間水平對齊：商品圖片、商品名稱（一到兩行）、商品描述（二到四行）以及「立即購買」按鈕。無論各卡片的標題和描述包含多少文字，按鈕必須在每一欄的相同垂直位置。

**使用 subgrid 之前——flex 欄的變通方案：**

```css
/* 每張卡片是一個 flex 欄容器 */
.card {
  display: flex;
  flex-direction: column;
  border: 1px solid #ccc;
  padding: 1rem;
}

/* 將按鈕推到卡片底部 */
.card button {
  margin-top: auto;
}
```

這個做法能讓按鈕貼齊各自卡片的底部，但同列的各張卡片高度不同（父層網格中最高的卡片決定了列高）。矮一點的卡片，其按鈕的位置高於高一點的卡片——兄弟元素之間沒有水平對齊。

為了繞過這個問題，工程師會為各內部區塊加入固定最小高度：

```css
.card img    { min-height: 200px; }
.card h2     { min-height: 3.5rem; }  /* 足夠容納兩行 */
.card p      { min-height: 6rem; }    /* 足夠容納四行 */
```

這些魔法數值非常脆弱。加入更長的商品名稱，或把 UI 翻譯成其他語言，版面就會再次壞掉。

**使用 subgrid 之後——宣告式軌道對齊：**

```css
.product-grid {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  grid-template-rows: repeat(4, auto);
  gap: 1rem;
}

.card {
  display: grid;
  grid-row: span 4;
  grid-template-rows: subgrid;
}
```

每張卡片跨越四個父層列軌道，並將其四個子元素——圖片、標題、描述、按鈕——映射到這些軌道上。父層網格控制軌道的尺寸。三張卡片中最高的標題決定標題軌道的高度；最長的描述決定描述軌道的高度。每個邏輯列中的所有元素都會自動對齊到完全相同的基準線，無需任何固定數值，也不需要 JavaScript。

## 最佳實踐

- MUST 讓子網格元素 span 其參與的父層軌道數量。一張有四個內部列的卡片需要 `grid-row: span 4`，這樣父層才會為子網格分配四條軌道。若 span 值不正確，子網格可用的父層軌道數量會少於子元素數量，版面會發生非預期的塌陷。
- SHOULD 在任何多卡片或多項目版面配置中使用 subgrid，只要兄弟元素之間的內部對齊很重要——商品卡片、定價表、表單網格、功能比較表、含說明文字的圖片畫廊。
- SHOULD 當列數超過三列時，為父層軌道命名。具名線段能讓人一眼看出每條軌道對應卡片的哪個語義區塊。

  ```css
  .product-grid {
    grid-template-rows:
      [card-img-start]   auto
      [card-img-end card-title-start]   auto
      [card-title-end card-desc-start]  auto
      [card-desc-end card-cta-start]    auto
      [card-cta-end];
  }
  ```

- SHOULD NOT 在子元素數量少於父層已分配軌道數量時套用 subgrid。子網格中沒有子元素的軌道不會自動收合——它們仍然存在，可能造成非預期的間距。
- MAY 在兩個軸向同時使用 subgrid，處理複雜的對齊表單版面配置。若表單的標籤和輸入框需要共享欄軌道（標籤欄 / 輸入框欄），且同時需要與相鄰區塊共享列軌道，則 `grid-template-rows: subgrid; grid-template-columns: subgrid` 兩者同時使用能帶來最佳效果。
- SHOULD 了解子網格元素上的 `gap` 會被忽略——子網格繼承父層網格的間距。若需調整子網格內部的間距，應修改父層的 `gap`、`row-gap` 或 `column-gap`。
- MAY 在子網格的子元素上搭配使用 `align-self` 和 `justify-self`，在繼承的軌道內微調對齊方式。

## 設計思維

### 為什麼網格子元素預設無法共享父層軌道

CSS Grid Level 1 在設計時，將每個網格項目定義為為其子元素建立一個新的獨立版面配置上下文。這是一個刻意的範疇決策：Grid Level 1 專注於網格容器與其直接子元素之間的關係，規格並未定義任何讓孫元素參與祖父元素軌道的機制。

根本原因在於架構層面。CSS Grid 的軌道尺寸由直接子元素的尺寸以及作者指定的明確大小共同決定。若允許孫元素影響軌道尺寸，規格就必須定義一種新的向上依賴關係——子元素的內容影響祖先元素的軌道尺寸——這會大幅增加版面演算法的複雜度。Level 1 完全迴避了這個複雜性。

結果是：每個網格項目從父層網格的角度看都是一個不透明的盒子。無論網格項目內部是一個扁平的段落，還是一個深度巢狀的多列結構，父層網格看到的都只是一個盒子。這就是為什麼在 Grid Level 1 中，「讓按鈕在同一列對齊」的問題無法在不借助外部工具的情況下解決。

### 生態系如何應對這個限制

在 subgrid 出現之前，有四種業界標準的模式：

**Flexbox 欄排列搭配 `margin-top: auto`** 是最常見的做法。它至少能保證按鈕貼齊卡片底部邊緣。搭配父層網格的 `align-items: stretch`（預設值），所有卡片都會拉伸至最高兄弟元素的高度，因此按鈕在視覺上都處於同一高度——但這僅適用於只有一個 CTA 的卡片。一旦在描述和按鈕之間加入第二個操作或徽章，立即失效。

**每個區塊固定最小高度**在生產環境的設計系統中被廣泛使用，通常以設計 token 的形式編碼。設計團隊量測預期中最高的內容，加上緩衝，將其固定為最小高度。這需要隨著內容變更持續維護，且在不同語言和螢幕尺寸下天生脆弱。

**JavaScript `ResizeObserver` 均等化**是 subgrid 出現前最穩健的解決方案。一個小型工具程式觀察每一列的卡片，找出每個語義插槽（標題、描述）中最高的元素，再對所有兄弟元素套用 `min-height`。Masonry 等函式庫和 CSS Grid polyfill 都包含類似的工具程式。代價是：JavaScript 必須執行並完成，版面才能在視覺上正確；在 SSR 應用的水合過程中，使用者會看到版面閃爍；每當 DOM 發生變化，觀察器必須拆除並重新建立。

**CSS Grid 搭配具名區域與 `display: contents`** 作為純 CSS 的變通方案曾被探索過。對卡片元素設定 `display: contents` 會讓卡片的子元素成為父層網格的直接子元素，使其能直接參與父層軌道。這雖然有效，但會破壞卡片作為樣式單元的性質——你無法再對卡片元素本身套用框線、背景、內距或 overflow，因為 `display: contents` 會完全移除該元素的盒子。

### 為什麼 subgrid 在架構上更優秀

Subgrid 在正確的抽象層次上解決了問題。父層網格仍然是軌道尺寸的決策者。子網格元素參與這些軌道，而非與其對抗。子網格元素的子元素在軌道尺寸計算方面，被視為父層網格的直接子元素；但在所有其他 CSS 用途上（繼承、`display`、`position`、事件），它們仍然在邏輯上是父元素的子元素。

相較於各種變通方案的關鍵優勢：

- **宣告式**：對齊關係以 CSS 表達，而非以 JavaScript 計算。瀏覽器的版面引擎在與其他所有事物相同的計算階段處理它。
- **具彈性**：內容可以自由變更——更長的標題、翻譯後的字串、動態資料——版面會自動適應，因為軌道尺寸由實際內容驅動。
- **可組合**：使用 subgrid 的卡片仍然是正常的 DOM 元素。它可以有框線、背景、內距、捲動和 overflow。`display: contents` 的變通方案犧牲了這一切。
- **無固定數值**：不需要維護魔法 `min-height` 常數，也不需要在內容策略改變時更新設計 token。

更廣泛的架構啟示是，subgrid 將對齊責任從子元素移交給父層，而這本來就是它應該歸屬的地方。父層網格了解其欄和列的語義結構；子元素（卡片）了解自己的內部結構；subgrid 提供橋樑，讓兩個層次都能描述各自所知道的內容，而不需要任何一方去量測對方的尺寸。

### 最簡模式——必記的 subgrid 核心寫法

```css
/* 父層：宣告每個項目 N 列的網格 */
.product-grid {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  grid-template-rows: repeat(4, auto); /* 每張卡片 4 列 */
  gap: 1rem;
}

/* 子元素：參與父層的列軌道 */
.card {
  display: grid;
  grid-row: span 4;              /* 跨越相同的 N 列 */
  grid-template-rows: subgrid;   /* 使用父層軌道，而非自行定義 */
}
```

`.card` 上的兩個關鍵宣告是 `grid-row: span 4` 和 `grid-template-rows: subgrid`，它們永遠成對出現。span 值告訴父層要分配多少條軌道；subgrid 值告訴卡片要將分配到的軌道用於其自身的子元素。

### 具名軌道變體

當列數超過三列時，為軌道命名能提升可維護性：

```css
.product-grid {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  grid-template-rows:
    [card-img-start]  auto
    [card-img-end card-title-start]  auto
    [card-title-end card-desc-start] auto
    [card-desc-end card-cta-start]   auto
    [card-cta-end];
  gap: 1rem;
}

.card {
  display: grid;
  /* 父層的具名線段會被繼承到子網格中 */
  grid-row: card-img-start / card-cta-end;
  grid-template-rows: subgrid;
}
```

父層的具名線段在子網格內部可用。子網格中的子元素可以使用 `grid-row: card-title-start / card-title-end` 明確地固定到標題軌道——當卡片變體需要跳過圖片軌道時特別有用。

### 兩個軸向同時使用

對於標籤和輸入框需要共享欄軌道、同時需要與相鄰摘要面板逐列對齊的表單版面配置：

```css
.form-layout {
  display: grid;
  grid-template-columns: [label-start] 120px [label-end input-start] 1fr [input-end];
  grid-template-rows: repeat(5, auto);
  gap: 0.75rem;
}

.form-section {
  display: grid;
  grid-column: 1 / -1;               /* 跨越所有欄 */
  grid-row: span 3;                   /* 跨越 3 個父層列 */
  grid-template-columns: subgrid;    /* 繼承標籤 + 輸入框欄 */
  grid-template-rows: subgrid;       /* 繼承列軌道 */
}
```

兩個軸向可以同時使用 subgrid。`.form-section` 上的 `grid-template-columns: subgrid` 繼承了具名的 `label` 和 `input` 欄；`grid-template-rows: subgrid` 繼承了列軌道。`.form-section` 的子元素在兩個軸向上都被放置到父層軌道中。

## 瀏覽器支援

| 瀏覽器  | 首次支援版本 | 備註 |
|---------|------------|------|
| Chrome  | 117        | 2023 年 9 月推出 |
| Firefox | 71         | 2019 年 12 月推出——第一個支援 subgrid 的瀏覽器 |
| Safari  | 16         | 2022 年 9 月推出 |
| Edge    | 117        | 基於 Chromium；與 Chrome 同步 |

Firefox 在 2019 年 12 月搶先推出了 subgrid，比 Chrome 早了將近四年。Safari 在 2022 年 9 月推出支援，Chrome 和 Edge 則在 2023 年 9 月跟進，實現了跨瀏覽器可用性。

2024 年起達到 Baseline Widely Available 狀態，全球覆蓋率超過 95%。MDN 相容性資料：[CSS subgrid 瀏覽器相容性](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Grid_layout/Subgrid#browser_compatibility)。

針對現代瀏覽器的生產環境無需加上 `@supports` 防護。若應用程式必須支援上述版本以前的舊瀏覽器，建議使用 flexbox 欄搭配按鈕 `margin-top: auto` 作為安全的回退方案：

```css
/* 回退方案：flex 欄，按鈕貼底 */
.card {
  display: flex;
  flex-direction: column;
}

.card button {
  margin-top: auto;
}

/* 漸進增強：支援時使用 subgrid 對齊 */
@supports (grid-template-rows: subgrid) {
  .product-grid {
    display: grid;
    grid-template-columns: repeat(3, 1fr);
    grid-template-rows: repeat(4, auto);
    gap: 1rem;
  }

  .card {
    display: grid;
    grid-row: span 4;
    grid-template-rows: subgrid;
  }
}
```
