# [FEE-11104] View Transitions — 第二層級（跨文件）

:::info
在網站的每個頁面加入一個 CSS at-rule，瀏覽器就會自動為頁面導航播放過渡動畫——不需要 JavaScript、不需要轉換為 SPA、不需要框架。
:::

:::warning Limited Availability
目前僅支援 Chrome 126+/Edge 126+。Firefox 與 Safari 的支援仍在進行中。
在正式環境使用前，請確認 [MDN 相容性表格](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@view-transition#browser_compatibility)。
:::

## 背景

View Transitions 第一層級引入了 `document.startViewTransition()` 作為 JavaScript API，用於在單一頁面內為 DOM 狀態變更製作動畫。它解決了快照時序競態條件，讓 SPA 的過渡動畫不再脆弱。但第一層級有一個架構邊界無法跨越：文件邊界。

當瀏覽器跟隨 `<a href>` 連結到不同 URL 時，它會在新文件的 JavaScript 有任何執行機會之前，就銷毀當前文件的 JavaScript 執行環境。`startViewTransition()` 呼叫只能在活躍的文件內部執行——沒有任何 JavaScript 鉤子能跨越兩個文件之間的差距。等到新頁面的腳本執行時，舊頁面的像素內容已消失，快照時機已錯過。

這個邊界是瀏覽器導航模型的基本屬性。這不是第一層級 API 實作的限制——而是任何 JavaScript API 在整頁導航中能做什麼的架構性約束。

其結果是，多頁應用程式（MPA）架構——使用純 HTML、Astro、VitePress、HTMX 或任何產生真實 URL 導航的伺服器渲染框架所建立的網站——從第一層級中得不到任何好處。它們的導航會產生熟悉的硬切：舊頁面消失，新頁面出現，沒有任何動畫。

傳統的解決方法是透過在 JavaScript 中攔截連結點擊、用 `fetch()` 取得下一頁的 HTML，並在不進行真實導航的情況下將其替換到 DOM 中，將 MPA 轉換為偽 SPA。這個方法恢復了呼叫 `startViewTransition()` 的能力，但代價高昂：路由器必須處理歷史記錄管理、捲動位置還原、焦點管理和漸進增強。Astro 的 `<ClientRouter>` 和 Swup.js 都實作了這個模式。對於有數百個靜態頁面的網站，SPA 路由的基礎建設成本往往與效益不成比例。

第二層級在平台層面解決了這個問題。它不要求 JavaScript 協調快照，而是讓快照機制變為宣告式：在離場和進場頁面各加一個 CSS at-rule，就足以讓瀏覽器自動將導航包裝在與第一層級相同的快照並播放動畫的管線中。

結果是 MPA 過渡成為 CSS 關注點，而非 JavaScript 關注點。不需要路由層，不需要 `fetch` 攔截，不需要歷史記錄管理——只需在每個頁面的樣式表中加入一個聲明。

### 為什麼 2024–2026 年 MPA 再度重要

業界部分轉向 SPA，是因為流暢導航帶來的感知 UX 優勢。有了第二層級，這個優勢對 MPA 也適用，且不需要承擔複雜度成本。同時，幾股力量正在推動開發者回歸 MPA 架構：

- **Astro**（靜態網站優先，預設零 JS）成為內容密集的文件和行銷網站的主流選擇。
- **VitePress** 為大多數主要開源文件網站（Vue、Vite、Vitest、Rollup、Pinia 等）提供支援。
- **HTMX** 讓伺服器驅動的互動性不需要客戶端路由即可實現。
- **Core Web Vitals** 偏好伺服器渲染的 HTML 以獲得初始載入效能。

這些架構都會產生真實的導航。第二層級為所有這些架構帶來 SPA 品質的過渡動畫。

## 情境

你正在維護一個以純 HTML（或 VitePress、或 Astro）建立的文件網站。網站有一個持久的網站標題，包含產品 Logo 和導航連結。目前，頁面之間的點擊會產生硬切：舊頁面消失，新頁面出現，沒有任何連續感。

你希望：

- 在每次導航時，用流暢的交叉淡入淡出動畫過渡頁面根部。
- 讓網站標題在導航期間視覺上保持連續——它應該看起來像是在原地保持，而不是與其他內容一起閃爍。
- 遵守 `prefers-reduced-motion`——選擇不使用動畫的使用者獲得即時導航。
- 支援未實作第二層級的瀏覽器——它們回退到正常導航，不產生任何錯誤。

需求：

- 不修改 JavaScript。
- 不引入 SPA 路由層。
- 適用所有同源導航。
- 純 CSS 交付。

使用 View Transitions 第二層級，只需在全局樣式表中加入兩個 CSS 區塊，即可滿足所有四項需求。

## 最佳實踐

- MUST 在**離場頁面和進場頁面**都加入 `@view-transition { navigation: auto; }`。只有兩個文件都選擇加入時，過渡才會觸發。如果任一頁面缺少 at-rule——例如，你未控制的外部頁面、或尚未更新的頁面——就不會觸發過渡，導航正常進行。這是安全的預設行為：缺少選擇加入會靜默降級為即時導航，而不是造成任何損壞。

- MUST 使用 `@media (prefers-reduced-motion: reduce)` 進行測試，並為已請求的使用者選擇退出過渡：

  ```css
  @media (prefers-reduced-motion: reduce) {
    @view-transition {
      navigation: none;
    }
  }
  ```

  將此區塊與 `@view-transition { navigation: auto; }` 宣告並排放在全局樣式表中。媒體查詢優先，會為偏好減少動態效果的使用者覆蓋 at-rule。

- SHOULD 將 `view-transition-name` 限制在真正跨導航持續存在的元素上。網站標題、持久導航列或出現在每個頁面上的主角圖片是適合的候選。頁面之間完全改變的正文內容則不適合——為其指定 `view-transition-name` 會產生不相似內容的交叉淡入淡出，效果比預設的根部交叉淡入淡出更差。

- SHOULD NOT 將 `view-transition-name` 套用到跨導航 DOM 形狀不可預測的元素。如果元素在一個頁面上存在但在另一個頁面上不存在，瀏覽器會建立未配對的快照，結果是原本不應動畫化的內容出現意外的淡入或淡出。

- MAY 使用 `pageswap` 和 `pagereveal` 事件為列表到詳細頁的共享元素過渡動態指派 `view-transition-name`。例如，在部落格索引中，每個文章卡片可以在導航前接收一個符合其文章 ID 的 `view-transition-name`，使卡片在詳細頁中變形為文章主角圖片：

  ```js
  // 在列表頁（離場）：pageswap
  document.addEventListener('pageswap', (e) => {
    if (!e.viewTransition) return;
    const articleId = getNavigatingArticleId(); // 從目標 URL 推導
    const card = document.querySelector(`[data-article-id="${articleId}"]`);
    if (card) {
      card.style.viewTransitionName = `article-${articleId}`;
    }
  });

  // 在詳細頁（進場）：pagereveal
  document.addEventListener('pagereveal', (e) => {
    if (!e.viewTransition) return;
    const articleId = getArticleIdFromURL(); // 從當前 URL 推導
    const hero = document.querySelector('.article-hero');
    if (hero) {
      hero.style.viewTransitionName = `article-${articleId}`;
    }
  });
  ```

- MAY 使用 `sessionStorage` 在導航邊界傳遞狀態，因為 `pageswap` 和 `pagereveal` 在不同文件中執行。在 `pageswap` 中將導航元素的 ID 寫入 `sessionStorage`；在 `pagereveal` 中讀取以識別正確的元素進行命名。

- SHOULD 驗證跨文件過渡只對同源導航觸發。瀏覽器會自動強制執行此規則——無論選擇加入狀態如何，跨源導航永遠不會觸發跨文件 view transitions。

## 設計思維

### 為什麼舊文件的 JS 執行環境無法被使用

當瀏覽器處理 `<a href>` 點擊時，導航生命週期為：

1. 當前文件的 `unload` 事件觸發。
2. 當前文件的渲染環境被拆除。
3. 新 URL 的網路請求開始（或使用快取回應）。
4. 新文件被解析，其腳本執行。

步驟 2 在步驟 4 之前發生。無法使用 JavaScript 跨越這個差距協調快照時序，因為兩個文件不會同時存活。舊文件的 `startViewTransition()` 需要新文件的 "after" 快照——但新文件尚未渲染。新文件的 `startViewTransition()` 需要舊文件的 "before" 快照——但舊文件已不再存在。

這不是缺少 API 介面；這是瀏覽器進程模型的結果。跨源導航可能完全切換到新的渲染進程，使共享記憶體或同步化成為不可能。

### 宣告式模型：CSS 驅動快照時序

第二層級透過將選擇加入機制移至 CSS，並將快照管理移入瀏覽器導航基礎設施來解決這個問題。瀏覽器的導航管線已經可以存取離場頁面（它控制何時拆除它）和進場頁面（它控制何時渲染它）。透過在這兩個時刻插入快照擷取點，瀏覽器可以在不需要任何 JavaScript 協調的情況下產生 before/after 快照。

`@view-transition { navigation: auto; }` at-rule 是告知瀏覽器的信號：「在導航離開或到達此頁面時，使用快照機制。」如果兩個頁面都發出選擇加入信號，瀏覽器就知道可以安全地：

1. 在拆除離場頁面之前擷取其快照。
2. 載入並初始化進場頁面。
3. 在首次渲染之前擷取進場頁面的快照。
4. 使用與第一層級相同的偽元素樹在兩個快照之間播放動畫。

這在架構上與第一層級不同。第一層級是**命令式**的：開發者明確呼叫 `startViewTransition()` 並控制其觸發時機。第二層級是**宣告式**的：瀏覽器根據兩個文件上 CSS at-rule 的存在來決定何時觸發。

宣告式模型對導航本質上更加穩健，因為瀏覽器對每個文件生命週期階段發生的時機有精確的知識。開發者不需要攔截點擊、管理 Promise，或跨兩個執行環境協調。

### `pageswap` 和 `pagereveal` 事件作為逃生出口

完全宣告式的路徑（純 CSS，無 JS）對於整頁交叉淡入淡出和持久元素變形效果良好，其中 `view-transition-name` 可以靜態設定在樣式表中。然而，某些過渡需要動態名稱指派——特別是列表到詳細頁的過渡，每次導航的共享元素都不同。

為此，第二層級引入了兩個新的文件事件：

**`pageswap`** 在離場文件上觸發，就在最終快照被擷取之前。此時，離場文件仍然活躍。事件的 `viewTransition` 屬性在跨文件過渡即將觸發時公開 `ViewTransition` 物件，否則為 `null`。使用 `pageswap` 為正在離開的元素指派 `view-transition-name`。

**`pagereveal`** 在進場文件上觸發，在其首次渲染之前。此時，新文件的 DOM 已就緒但尚未繪製任何內容。使用 `pagereveal` 為正在到來的元素指派 `view-transition-name`。

兩個事件都透過 `viewTransition` 屬性接收相同的 `ViewTransition` 物件，這允許在最後時刻決定此導航不應動畫化時呼叫 `viewTransition.skipTransition()`。

這些事件對每次同源跨文件導航都會觸發，而不僅是已啟用 view transitions 的導航。在根據過渡狀態操作名稱或做出決定之前，務必檢查 `e.viewTransition`。

### 第二層級過渡與第一層級的比較

偽元素樹完全相同。一旦跨文件過渡啟動，瀏覽器就會建立相同的覆蓋層：

```
::view-transition
  ::view-transition-group(root)
    ::view-transition-image-pair(root)
      ::view-transition-old(root)
      ::view-transition-new(root)
  ::view-transition-group(site-header)
    ::view-transition-image-pair(site-header)
      ::view-transition-old(site-header)
      ::view-transition-new(site-header)
```

第一層級所有的 CSS 自定義技術——針對 `::view-transition-old` 和 `::view-transition-new`、編寫自定義 `@keyframes`、使用 `::view-transition-group` 進行變形動畫——對第二層級過渡的適用方式完全相同。

唯一的差異是過渡如何啟動：第一層級需要明確的 JS 呼叫，第二層級在兩個頁面都選擇加入時自動觸發。

### 導航類型過濾

`auto` 值會對 `push`、`replace` 和 `traverse` 導航觸發過渡。`traverse` 導航是透過瀏覽歷史記錄的前進/後退導航。如果你想為前進導航播放動畫但不為後退導航——一個常見的 UX 模式——你可以在 `pageswap` 或 `pagereveal` 中檢查 `e.viewTransition.navigationType`，並有選擇地呼叫 `skipTransition()`。

未來的第二層級草案包括在 `@view-transition` 中加入 `types` 描述符的提案，以在不使用 JavaScript 的情況下啟用 CSS 層級的過濾，遵循與導航類型 `@media` 查詢相同的模式。查看 CSSWG 草案以了解當前狀態。

## 範例

一個兩頁 MPA 文件網站。兩個頁面共享相同的樣式表。持久的網站標題在導航期間流暢地變形，而主要內容交叉淡入淡出。

`page-a.html`：

```html
<!DOCTYPE html>
<html lang="zh-TW">
<head>
  <style>
    @view-transition {
      navigation: auto;
    }

    @media (prefers-reduced-motion: reduce) {
      @view-transition {
        navigation: none;
      }
    }

    header {
      view-transition-name: site-header;
      background: #1a1a2e;
      color: white;
      padding: 1rem 2rem;
      display: flex;
      align-items: center;
      gap: 1rem;
    }

    header a {
      color: #a8d8ea;
      text-decoration: none;
    }

    main {
      padding: 2rem;
      max-width: 800px;
      margin: 0 auto;
    }

    /* 可選：自定義根部交叉淡入淡出持續時間 */
    ::view-transition-old(root),
    ::view-transition-new(root) {
      animation-duration: 0.3s;
    }
  </style>
</head>
<body>
  <header>
    <span>My Documentation Site</span>
    <nav>
      <a href="page-a.html">Introduction</a>
      <a href="page-b.html">Chapter 1</a>
    </nav>
  </header>
  <main>
    <h1>Introduction</h1>
    <p>Welcome to the documentation. This is page A.</p>
    <p><a href="page-b.html">Go to Chapter 1 &rarr;</a></p>
  </main>
</body>
</html>
```

`page-b.html`（相同樣式表，不同內容——標題視覺上持續存在）：

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <style>
    @view-transition {
      navigation: auto;
    }

    @media (prefers-reduced-motion: reduce) {
      @view-transition {
        navigation: none;
      }
    }

    header {
      view-transition-name: site-header;
      background: #1a1a2e;
      color: white;
      padding: 1rem 2rem;
      display: flex;
      align-items: center;
      gap: 1rem;
    }

    header a {
      color: #a8d8ea;
      text-decoration: none;
    }

    main {
      padding: 2rem;
      max-width: 800px;
      margin: 0 auto;
    }

    ::view-transition-old(root),
    ::view-transition-new(root) {
      animation-duration: 0.3s;
    }
  </style>
</head>
<body>
  <header>
    <span>My Documentation Site</span>
    <nav>
      <a href="page-a.html">Introduction</a>
      <a href="page-b.html">Chapter 1</a>
    </nav>
  </header>
  <main>
    <h1>Chapter 1</h1>
    <p>This is the first chapter. The header above persisted from the previous page.</p>
    <p><a href="page-a.html">&larr; Back to Introduction</a></p>
  </main>
</body>
</html>
```

### 導航時發生了什麼

當使用者點擊「Go to Chapter 1」：

1. 瀏覽器識別出導航為同源。
2. 它在離場頁面（`page-a.html`）上檢查 `@view-transition { navigation: auto; }`——存在。
3. 它在離場文件上觸發 `pageswap`。任何 `pageswap` 監聽器可以在此時調整 `view-transition-name` 指派。
4. 瀏覽器擷取 "before" 快照：`site-header`（持久標題）和 `root`（完整頁面）。
5. 瀏覽器載入 `page-b.html` 並解析其 DOM。
6. 它在進場頁面上檢查 `@view-transition { navigation: auto; }`——存在。
7. 它在首次渲染前在進場文件上觸發 `pagereveal`。
8. 瀏覽器擷取 "after" 快照：`site-header`（B 頁上的標題，相同位置和尺寸）和 `root`。
9. 過渡播放動畫：`site-header` 在原地變形（由於在兩個頁面上尺寸和位置相同，本質上是在相同位置的交叉淡入淡出），而 `root` 交叉淡入淡出改變的正文內容。

由於標題在兩個頁面上具有相同的高度、背景色和位置，`site-header` 的變形是不可見的——看起來像是標題從未移動。只有 `main` 內容區域交叉淡入淡出，給人持久導航的感覺。

### 使用 pageswap / pagereveal 進行跨頁共享元素變形

對於有文章列表頁和文章詳細頁的部落格，文章卡片可以變形為文章主角圖片：

```js
// 共享工具：從 URL 字串推導文章 ID
function getArticleIdFromHref(href) {
  const url = new URL(href, location.href);
  return url.searchParams.get('id') || url.pathname.split('/').pop();
}

// 在列表頁：在快照前為被點擊的卡片指派名稱
document.addEventListener('pageswap', (e) => {
  if (!e.viewTransition) return;
  // Note: :focus/:active may already be cleared at pageswap time.
  // For production use, capture the target in a click handler instead.
  const link = document.querySelector('a:focus, a:active');
  if (!link) return;
  const articleId = getArticleIdFromHref(link.href);
  const card = document.querySelector(`[data-id="${articleId}"] img`);
  if (card) {
    card.style.viewTransitionName = `article-hero-${articleId}`;
  }
});
```

```js
// 在詳細頁：在首次渲染前為主角圖片指派名稱
document.addEventListener('pagereveal', (e) => {
  if (!e.viewTransition) return;
  const articleId = document.querySelector('article').dataset.id;
  const hero = document.querySelector('.hero-image');
  if (hero && articleId) {
    hero.style.viewTransitionName = `article-hero-${articleId}`;
  }
});
```

兩側的 `view-transition-name` 值相符（`article-hero-${articleId}`），因此瀏覽器配對離場的卡片圖片與進場的主角圖片，並在導航邊界產生變形動畫。

:::warning `pageswap` 中 `:focus` 與 `:active` 的可靠性
上述範例中使用的 `a:focus, a:active` 選擇器僅為簡化示意。當 `pageswap` 觸發時，瀏覽器可能已清除觸發導航的錨點元素上的 `:focus` 與 `:active` 狀態，因此此查詢可能靜默回傳 `null`。在正式環境中，建議使用下一節說明的 `sessionStorage` 模式：在導航開始前於 `click` 處理函式中捕捉目標元素（或其識別符），再於 `pageswap` 或 `pagereveal` 中讀取。
:::

### 用 keyframes 自定義交叉淡入淡出

預設根部過渡是 300ms 交叉淡入淡出。將其替換為方向性滑動：

```css
@keyframes slide-from-right {
  from {
    opacity: 0;
    transform: translateX(40px);
  }
}

@keyframes slide-to-left {
  to {
    opacity: 0;
    transform: translateX(-40px);
  }
}

::view-transition-old(root) {
  animation: slide-to-left 0.3s ease-in forwards;
}

::view-transition-new(root) {
  animation: slide-from-right 0.3s ease-out forwards;
}

@media (prefers-reduced-motion: reduce) {
  @view-transition {
    navigation: none;
  }
}
```

這與第一層級的 keyframe 自定義完全相同。無論過渡是由 `startViewTransition()` 還是跨文件選擇加入啟動，偽元素的行為都相同。

### 使用 sessionStorage 跨導航邊界傳遞狀態

由於 `pageswap` 和 `pagereveal` 在不同文件中觸發，它們不共享 JavaScript 變數。使用 `sessionStorage` 傳遞少量狀態：

```js
// pageswap：記錄使用者點擊了哪篇文章
document.addEventListener('pageswap', (e) => {
  if (!e.viewTransition) return;
  const link = document.querySelector('a:focus');
  if (link) {
    const id = getArticleIdFromHref(link.href);
    sessionStorage.setItem('transitioningArticleId', id);
  }
});

// pagereveal：讀取值並指派名稱
document.addEventListener('pagereveal', (e) => {
  if (!e.viewTransition) return;
  const id = sessionStorage.getItem('transitioningArticleId');
  sessionStorage.removeItem('transitioningArticleId');
  if (!id) return;
  const hero = document.querySelector('.hero-image');
  if (hero) {
    hero.style.viewTransitionName = `article-hero-${id}`;
  }
});
```

這個模式有效，因為 `sessionStorage` 在同一個瀏覽器分頁內的同源導航間持久存在。

### 功能偵測

跨文件 view transitions 不需要 JavaScript 功能檢查，因為它們會靜默降級。如果瀏覽器不支援第二層級，`@view-transition` at-rule 會被忽略，正常導航繼續進行。沒有 JavaScript 錯誤，沒有佈局損壞。

然而，如果你正在編寫 `pageswap` 或 `pagereveal` 監聽器，請在 `e.viewTransition` 上加入防護，以避免在觸發事件但不填充 `viewTransition` 屬性的瀏覽器上出現空參考錯誤：

```js
document.addEventListener('pagereveal', (e) => {
  if (!e.viewTransition) return; // 在不支援的瀏覽器上安全退出
  // ...
});
```

對於純 CSS 使用（無 `pageswap`/`pagereveal`），不需要額外的功能偵測。

## 瀏覽器支援

| 瀏覽器  | 跨文件 View Transitions         | 備注 |
|---------|--------------------------------|------|
| Chrome  | 126                            | 主框架導航；iframe 支援稍後加入 |
| Edge    | 126                            | 基於 Chromium |
| Firefox | 進行中                          | 積極開發中；尚未發布 |
| Safari  | 進行中                          | 積極開發中；尚未發布 |

`pageswap` 和 `pagereveal` 事件在 Chrome 126+ 和 Edge 126+ 中可用。兩個事件對同源跨文件導航都會觸發，無論 view transition 是否啟用。

跨文件 view transitions 預計在 Firefox 和 Safari 發布支援後達到 Baseline。關注 [MDN 相容性表格](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@view-transition#browser_compatibility) 以了解當前狀態。

CSS `@supports` 無法可靠地偵測跨文件 view transitions，因為 `@view-transition` at-rule 可能被未實作導航過渡的瀏覽器解析（它們可能因其他原因支援該 at-rule）。最安全的生產模式是無條件加入 at-rule，讓不支援的瀏覽器忽略它。
