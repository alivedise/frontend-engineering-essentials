# [FEE-11300] CSS Carousel Primitives — CSS 輪播原語

:::info
純 CSS 打造完整輪播元件，完全不需要 JavaScript：圓點指示器、前後按鈕、鍵盤導覽、觸控支援。
:::

:::warning Limited Availability
目前僅支援 Chrome 135+ 與 Edge 135。Firefox 與 Safari 尚未支援。
在正式部署前請確認 MDN 相容性表。跨瀏覽器支援必須（REQUIRED）提供 JavaScript polyfill 或漸進增強回退方案。
:::

## 背景

輪播（Carousel）是網頁上最常見的 UI 模式之一，同時也是最難正確實作的模式之一。

一個可上線的輪播需要具備以下所有功能：

- **捲動追蹤**：偵測使用者捲動或滑動時哪張投影片正在可視範圍內
- **圓點指示器**：建立指示元素，並讓其啟用狀態與捲動位置同步
- **前後按鈕狀態**：在起始位置停用「上一張」按鈕，在末端停用「下一張」按鈕
- **鍵盤導覽**：允許使用者用方向鍵操作
- **觸控/滑動支援**：處理 touchstart、touchmove、touchend 與速度計算
- **ARIA 屬性**：為螢幕閱讀器標記 roles、aria-label、aria-current、aria-disabled

不使用函式庫手刻輪播，意味著要為上述每一項功能自行寫程式碼：捲動追蹤、指示器同步、按鈕狀態、鍵盤處理、觸控手勢與 ARIA 接線。改用函式庫可以省去這些維護負擔，但會為頁面增加 JavaScript 體積：

- **Swiper**：功能最完整的選項，也是四者中最重的。完整打包檔（swiper-bundle.min.js）gzip 後約 47 KB，壓縮後（minified）約 150 KB。
- **Splide**：功能相近但體積較輕的替代方案。
- **Embla Carousel**：刻意精簡，圓點與按鈕的接線需自行處理。
- **Keen Slider**：刻意精簡，範圍與 Embla 相當。

這些函式庫都是正確且維護良好的選擇。問題在於：為什麼瀏覽器不能原生提供這個能力？

瀏覽器已經對原生互動控制項處理了同等複雜度的事務：

- `<input>`：鍵盤導覽、焦點管理、ARIA 狀態、系統樣式
- `<select>`：下拉定位、鍵盤選取、捲動行為、無障礙功能
- `<details>` / `<summary>`：展開收合切換、鍵盤支援、ARIA expanded 狀態

捲動容器（scroll containers）是頁面上互動性最高的介面之一。然而它們卻沒有任何原生控制項可以提供指示器、按鈕或離散快照點（snap point）感知。CSS Carousel Primitives 正是為了填補這個缺口。

你正在為電商頁面建立商品圖片相簿，相簿一次顯示一張圖片，配有圓點指示器與前後導覽。需求如下：

- 在行動裝置上支援觸控/滑動（不使用 JS）
- 具備鍵盤導覽無障礙功能
- 圓點高亮顯示當前可見的圖片
- 在第一張圖片時停用前一張按鈕；最後一張時停用下一張按鈕
- 不使用第三方 JavaScript 輪播函式庫
- 整個功能必須在靜態 HTML + CSS 頁面中運作（不需要建置步驟，不需要打包器）

在 CSS Carousel Primitives 出現之前，同時滿足這些需求，在沒有 JavaScript 的情況下是不可能的。使用 `::scroll-marker`、`::scroll-button()` 與捲動快照，CSS 現在可以直接滿足這組特定需求。

這些原語僅涵蓋上述六項需求，不多也不少。它們不提供自動播放、無限或循環捲動，也沒有可從程式碼控制輪播的 API。若相簿需要自動前進，或在最後一張投影片後循環回第一張，仍然需要搭配 JavaScript，或改用 JavaScript 取代這些原語。

## 視覺對比

| CSS 原語 | 瀏覽器自動處理的部分 |
|---|---|
| `scroll-snap-type` / `scroll-snap-align` | 快照物理效果：無論手勢速度為何，滑動、拖曳或捲動結束後，會將捲動位置定格在投影片邊界。 |
| `::scroll-marker` | 為每個快照目標建立一個可獲得焦點的指示器，將其插入標記群組，並將 `:target-current` 套用到當前可見投影片對應的標記上。 |
| `::scroll-button()` | 建立上一張/下一張控制項，在對應的捲動邊界停用，並在點擊或鍵盤啟動時捲動一個快照點。 |
| `scroll-marker-group` | 將產生的 `::scroll-marker-group` 定位在捲動容器之前或之後，並將標記組成類似 `tablist` 的複合介面元件。 |

## 範例

### 完整輪播：圓點指示器與前後按鈕

以下範例是純 HTML 與 CSS 的完整功能圖片輪播。直接複製並在 Chrome 135+ 或 Edge 135+ 中開啟即可。

```html
<!DOCTYPE html>
<html lang="zh-TW">
<head>
  <meta charset="UTF-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1.0" />
  <title>CSS Carousel Primitives</title>
  <style>
    body {
      font-family: system-ui, sans-serif;
      padding: 24px;
      background: #f5f5f5;
    }

    /* ── 功能偵測包裝 ──────────────────────────────── */
    @supports (scroll-marker-group: after) {

      /* ── 輪播容器 ────────────────────────────────── */
      .carousel {
        position: relative;
        overflow-x: auto;
        scroll-snap-type: x mandatory;
        scroll-marker-group: after;
        display: flex;
        border-radius: 12px;
        max-width: 640px;
        margin: 0 auto;
        /* 按鈕點擊時平滑捲動 */
        scroll-behavior: smooth;
      }

      /* ── 每張投影片 ──────────────────────────────── */
      .carousel img {
        scroll-snap-align: start;
        flex-shrink: 0;
        width: 100%;
        aspect-ratio: 3 / 2;
        object-fit: cover;
        display: block;
      }

      /* ── 捲動標記群組（圓點指示器列） ──────────── */
      .carousel::scroll-marker-group {
        display: flex;
        justify-content: center;
        align-items: center;
        gap: 8px;
        padding: 10px 0 4px;
      }

      /* ── 個別圓點 ────────────────────────────────── */
      .carousel img::scroll-marker {
        content: '';
        width: 10px;
        height: 10px;
        border-radius: 50%;
        background: #ccc;
        border: 2px solid transparent;
        outline: 2px solid transparent;
        outline-offset: 2px;
        cursor: pointer;
        transition: background 0.2s, transform 0.2s;
      }

      /* ── 活動圓點 ────────────────────────────────── */
      /* :target-current 會在投影片目前可見時，套用在對應的 ::scroll-marker 上 */
      .carousel img::scroll-marker:target-current {
        background: #1a1a2e;
        transform: scale(1.2);
      }

      /* ── 圓點的焦點環 ────────────────────────────── */
      .carousel img::scroll-marker:focus-visible {
        outline: 2px solid #0066cc;
      }

      /* ── 前一張 / 下一張按鈕 ─────────────────────── */
      .carousel::scroll-button(inline-start),
      .carousel::scroll-button(inline-end) {
        position: absolute;
        top: 50%;
        transform: translateY(-50%);
        width: 36px;
        height: 36px;
        border: none;
        border-radius: 50%;
        background: rgba(0, 0, 0, 0.55);
        color: white;
        font-size: 1rem;
        line-height: 1;
        cursor: pointer;
        display: flex;
        align-items: center;
        justify-content: center;
        transition: background 0.15s;
      }

      .carousel::scroll-button(inline-start) {
        content: '←' / 'Previous slide';
        left: 8px;
      }

      .carousel::scroll-button(inline-end) {
        content: '→' / 'Next slide';
        right: 8px;
      }

      /* ── 懸停狀態 ────────────────────────────────── */
      .carousel::scroll-button(inline-start):hover,
      .carousel::scroll-button(inline-end):hover {
        background: rgba(0, 0, 0, 0.8);
      }

      /* ── 停用狀態（在捲動邊界時） ───────────────── */
      .carousel::scroll-button(inline-start):disabled,
      .carousel::scroll-button(inline-end):disabled {
        opacity: 0.3;
        cursor: not-allowed;
      }

      /* ── 按鈕的焦點環 ────────────────────────────── */
      .carousel::scroll-button(inline-start):focus-visible,
      .carousel::scroll-button(inline-end):focus-visible {
        outline: 2px solid #0066cc;
        outline-offset: 2px;
      }

      /* ── 減少動態效果 ────────────────────────────── */
      @media (prefers-reduced-motion: reduce) {
        .carousel {
          scroll-behavior: auto;
        }
        .carousel img::scroll-marker {
          transition: none;
        }
      }

    } /* end @supports */

    /* ── 不支援瀏覽器的回退方案 ─────────────────── */
    @supports not (scroll-marker-group: after) {
      .carousel {
        display: flex;
        overflow-x: auto;
        scroll-snap-type: x mandatory;
        max-width: 640px;
        margin: 0 auto;
        border-radius: 12px;
      }
      .carousel img {
        scroll-snap-align: start;
        flex-shrink: 0;
        width: 100%;
        aspect-ratio: 3 / 2;
        object-fit: cover;
      }
      .unsupported-notice {
        text-align: center;
        margin-top: 12px;
        color: #888;
        font-size: 0.875rem;
      }
    }

  </style>
</head>
<body>

  <div class="carousel" aria-label="商品圖片相簿">
    <img src="https://picsum.photos/seed/1/600/400" alt="投影片 1">
    <img src="https://picsum.photos/seed/2/600/400" alt="投影片 2">
    <img src="https://picsum.photos/seed/3/600/400" alt="投影片 3">
    <img src="https://picsum.photos/seed/4/600/400" alt="投影片 4">
    <img src="https://picsum.photos/seed/5/600/400" alt="投影片 5">
  </div>

  <p class="unsupported-notice">
    向左或向右滑動以瀏覽所有圖片。圓點指示器與前後按鈕需要 Chrome 135+。
  </p>

</body>
</html>
```

**完全不需要 JavaScript，你就能得到：**

- 觸控裝置上的左右滑動
- 點擊圓點跳至任意投影片
- 點擊箭頭按鈕逐張前後切換
- 箭頭按鈕在第一張與最後一張時自動停用
- 圓點獲得焦點時的方向鍵導覽
- 自動遵循 `prefers-reduced-motion`

### 最精簡版本（不含 @supports 包裝）

對於可控制瀏覽器環境的內部工具或僅限 Chrome 的場景，最基本的 CSS 如下：

```css
.carousel {
  overflow-x: auto;
  scroll-snap-type: x mandatory;
  scroll-marker-group: after;
  display: flex;
  scroll-behavior: smooth;
}

.carousel img {
  scroll-snap-align: start;
  flex-shrink: 0;
  width: 100%;
}

.carousel::scroll-marker-group {
  display: flex;
  gap: 8px;
  justify-content: center;
  padding: 8px 0;
}

.carousel img::scroll-marker {
  content: '';
  width: 10px;
  height: 10px;
  border-radius: 50%;
  background: #ccc;
}

.carousel img::scroll-marker:target-current {
  background: #333;
}

.carousel::scroll-button(inline-start) { content: '←' / 'Previous slide'; }
.carousel::scroll-button(inline-end) { content: '→' / 'Next slide'; }
```

`::scroll-button()` 上的 `content` 屬性是必要的。沒有它，偽元素不會渲染。

## 最佳實踐

- MUST 在 `::scroll-button()` 偽元素上加入可見的焦點樣式。鍵盤使用者依賴前後控制項進行導覽，看不見的焦點指示是無障礙功能上的缺失。
- MUST 為每個 `::scroll-button()` 提供可存取名稱，透過生成內容的替代文字（`content: '←' / 'Previous slide'`）或等效的 `aria-label` 達成。單純的箭頭符號對螢幕閱讀器來說毫無意義。
- MUST 在容器上加入 `scroll-snap-type`，並在每個項目上加入 `scroll-snap-align`。沒有捲動快照，scroll markers 就不對應到離散位置，功能會出現不可預期的行為。
- SHOULD 使用 `@supports (scroll-marker-group: after)` 限定 CSS 輪播功能，並為不支援的瀏覽器提供回退方案（靜態圖片條帶或 JS 輪播）。
- MUST NOT 在沒有 JavaScript polyfill 或漸進增強策略的情況下，將 CSS Carousel Primitives 部署到 Firefox 與 Safari 的正式環境。截至 2026 年，已上線支援僅限 Chrome/Edge。
- SHOULD 使用 `@media (prefers-reduced-motion: reduce)` 停用捲動動畫，同時保持指示器和按鈕的完整功能。使用者仍然需要導覽，只是不需要動畫效果。
- SHOULD 在捲動容器上提供可見標籤或 `aria-label`，向輔助技術傳達其用途。
- SHOULD 在輪播圖片上使用 `object-fit: cover` 與固定的 `aspect-ratio`，防止不同自然尺寸圖片間的版面位移（layout shift）。

## 設計思維

### 為何輪播需要 JavaScript

在 CSS Carousel Primitives 出現之前，CSS 沒有機制能夠：

1. **得知當前捲動位置**：CSS 無法觀測哪個快照目標（snap target）正在視窗中。JavaScript 監聽 `scroll` 事件並使用 `IntersectionObserver` 偵測當前活動的投影片。
2. **建立能回應捲動狀態的指示元素**：圓點指示器是普通的 DOM 元素（通常是 `<button>` 標籤），JavaScript 透過新增/移除 active class 名稱來更新它們。CSS 沒有任何偽元素能夠存在並從獨立的捲動容器接收狀態。
3. **以程式控制方式捲動至快照點**：當使用者點擊圓點或按鈕時，JavaScript 呼叫 `element.scrollTo()`。CSS 無法在回應點擊時觸發捲動，除了脆弱的 `:target` 錨點技巧之外。

### Swiper.js 如何解決這個問題

Swiper.js 實作了完整的 JavaScript 輪播：

- 附加 `pointermove` 和 `touchmove` 事件監聽器來追蹤滑動速度與方向
- 維護當前活動投影片的內部索引
- 投影片切換時：從前一個圓點移除 `swiper-slide-active`，加入到下一個圓點
- 將前後按鈕渲染為真實的 `<button>` DOM 元素，並綁定 `click` 監聽器
- 透過 JavaScript 動態添加 `aria-label` 和 `aria-current`

這是正確的行為：Swiper.js 處理了所有邊緣案例，代價是 JavaScript 執行時間、DOM 操作的開銷，以及打包體積。

### CSS 優先哲學

瀏覽器的原生控制項（`<input>`、`<select>`、`<details>`）之所以正確，是因為瀏覽器在內部處理了所有複雜性。開發者在 HTML 與 CSS 中宣告意圖；瀏覽器處理捲動物理、鍵盤事件、焦點管理與 ARIA 語意。

CSS Carousel Primitives 將同樣的哲學套用到捲動容器：

- `::scroll-marker`：瀏覽器建立並管理指示元素，將其啟用狀態與捲動位置連結，並自動路由鍵盤焦點
- `::scroll-button()`：瀏覽器建立並管理前後控制項，在捲動邊界處理停用狀態，並在點擊時觸發捲動事件
- `scroll-snap-type` / `scroll-snap-align`：瀏覽器處理快照物理、觸控速度與離散位置快照

## 深入探討

### `::scroll-marker` 的運作原理

`::scroll-marker` 是一個偽元素，可以宣告在捲動容器內的任何捲動快照目標（scroll snap target）上。宣告後，瀏覽器會建立一個可獲得焦點的指示元素，並將其插入 `::scroll-marker-group`。

關鍵行為：瀏覽器追蹤哪個快照目標當前在捲動容器的可視區域內，並自動將 `:target-current` 套用到對應的 `::scroll-marker`。這消除了每個 JavaScript 輪播都要實作的 `IntersectionObserver` + class 切換模式。

`content` 屬性必須設定（即使是 `''`）才能渲染標記。沒有 `content`，偽元素不會被產生。

### `:target-current`：活動狀態偽類別

`:target-current` 是隨 CSS Carousel Primitives 一起引入的新偽類別。它套用在其對應快照目標當前與捲動容器的快照視窗相交的 `::scroll-marker` 上。

請勿與以下偽類別混淆：

- `:target`：套用在與 URL 片段（例如 `#slide-1`）匹配的元素
- `:checked`：套用在已勾選的表單控制項
- `:focus`：套用在當前獲得焦點的元素

`:target-current` 專門用於「當前活動快照目標」的概念，且僅對 `::scroll-marker` 偽元素有效。

### `scroll-marker-group`：位置屬性

`scroll-marker-group: after` 在正常文件流中，將 `::scroll-marker-group` 偽元素定位於捲動容器內容之後：在水平輪播中，即圖片下方。

`scroll-marker-group: before` 則將其定位在前面，適用於希望指示器出現在頂部的垂直輪播。

`::scroll-marker-group` 本身預設是一個彈性容器（flex container），可以用標準版面屬性設定樣式。

### `::scroll-button()`：方向參數

`::scroll-button()` 接受邏輯方向關鍵字：

- `inline-start`：「上一張」按鈕（LTR 中為左側，RTL 中為右側）
- `inline-end`：「下一張」按鈕（LTR 中為右側，RTL 中為左側）
- `block-start`：向上捲動（用於垂直容器）
- `block-end`：向下捲動（用於垂直容器）

使用邏輯關鍵字（`inline-start` / `inline-end`）而非物理關鍵字（`left` / `right`），可自動確保從右至左書寫模式下的正確行為。

瀏覽器自動處理：

- 當捲動容器在起始邊界時停用 `::scroll-button(inline-start)`
- 當在末端邊界時停用 `::scroll-button(inline-end)`
- 點擊時觸發捲動事件，前進一個快照點
- 將鍵盤 Enter/Space 事件路由到對應的捲動動作

### 鍵盤導覽行為

`::scroll-marker-group` 作為複合介面元件（composite widget）接收焦點。獲得焦點後：

- 方向左 / 方向右（垂直輪播則用方向上 / 方向下）在標記間移動焦點
- 已獲焦點的標記所對應的快照目標捲動進入視窗
- Tab 鍵將焦點移出標記群組，移至頁面上下一個可獲焦點的元素

標記群組會向輔助技術回報其角色為 `tablist`，其方向鍵行為則遵循 [focusgroup](https://open-ui.org/components/scoped-focusgroup.explainer/) 模式，也就是一組相關控制項透過方向鍵在彼此之間移動焦點時所依循的標準複合介面元件模式。

### 漸進增強：推薦模式

```css
/* 基礎樣式：所有瀏覽器的靜態條帶 */
.carousel {
  display: flex;
  overflow-x: auto;
  scroll-snap-type: x mandatory;
  max-width: 640px;
}

.carousel img {
  scroll-snap-align: start;
  flex-shrink: 0;
  width: 100%;
  aspect-ratio: 3 / 2;
  object-fit: cover;
}

/* 增強輪播：在支援的瀏覽器中加入標記和按鈕 */
@supports (scroll-marker-group: after) {
  .carousel {
    scroll-marker-group: after;
    scroll-behavior: smooth;
  }

  .carousel::scroll-marker-group {
    display: flex;
    gap: 8px;
    justify-content: center;
    padding: 8px 0;
  }

  .carousel img::scroll-marker {
    content: '';
    width: 10px;
    height: 10px;
    border-radius: 50%;
    background: #ccc;
  }

  .carousel img::scroll-marker:target-current {
    background: #333;
  }

  .carousel::scroll-button(inline-start) { content: '←' / 'Previous slide'; }
  .carousel::scroll-button(inline-end) { content: '→' / 'Next slide'; }
}
```

在不支援的瀏覽器中，輪播會回退為可捲動、具快照功能的條帶：滑動或捲動仍可運作，但沒有圓點與前後按鈕。

### `::column::scroll-marker`：未來變體

CSS Overflow 5 規範包含一個計畫中的變體：`::column::scroll-marker`，用於多欄版面（multi-column layout）輪播，其中捲動目標是 CSS 欄（columns）而非個別子元素。截至 2026 年，這仍處於規範探索階段，尚未在任何瀏覽器中出貨。

## 瀏覽器支援

| 瀏覽器  | 首次支援版本 | 備註 |
|---------|------------|------|
| Chrome  | 135        | 完整支援：`::scroll-marker`、`::scroll-button()`、`:target-current`、`scroll-marker-group` |
| Firefox | —          | 尚未出貨；已列為 Interop 提案追蹤項目，並有對應的 Mozilla standards-position 議題正在討論中。截至 2026 年 7 月尚未公布出貨時程 |
| Safari  | —          | 尚未出貨；已列為 Interop 提案追蹤項目，並有對應的 WebKit standards-position 議題正在討論中。截至 2026 年 7 月尚未公布出貨時程 |
| Edge    | 135        | 基於 Chromium；與 Chrome 支援相同 |

功能偵測：

```css
@supports (scroll-marker-group: after) {
  /* 支援 CSS Carousel Primitives */
}
```

```js
const supportsCarouselPrimitives = CSS.supports('scroll-marker-group', 'after');
```

**正式部署指引：** 截至 2026 年 7 月，CSS Carousel Primitives 僅限 Chrome/Edge 支援。MUST NOT 在沒有其他方案的情況下，將其作為唯一的輪播實作部署到正式環境。使用 `@supports` 漸進增強，並為 Firefox 和 Safari 使用者保留 JavaScript 回退方案（或靜態捲動條帶）。待 Firefox 或 Safari 出貨支援後重新評估。
