# [FEE-11101] @starting-style — 無需 JavaScript 的進場動畫

:::info
明確宣告元素過渡動畫的起始狀態，讓對話框、Toast 通知、下拉選單都能以純 CSS 動畫進場，不需要任何 JavaScript 時機技巧。
:::

:::info Baseline Newly Available
Chrome 117+、Firefox 129+、Safari 17.5+ 已支援。請使用漸進增強方式相容舊版瀏覽器。
:::

## 背景

CSS `transition` 在兩個計算樣式狀態之間產生動畫。要達到這個效果，瀏覽器需要知道每個動畫屬性的「之前」和「之後」的值。當元素已在 DOM 中並且可見時，這運作得很完美：將 `opacity` 從 `1` 改為 `0`，或將 `transform` 從 `none` 改為 `translateY(-8px)`，瀏覽器有明確的前後狀態可以插值。

問題出在以 `display: none` 隱藏的元素。設定 `display: none` 時，瀏覽器不會渲染該元素，它沒有計算出的盒模型、沒有幾何資訊，也沒有可插值的屬性值。當你將它切換為 `display: block` 時，CSS 過渡沒有起始狀態可以從中動畫。元素直接以最終狀態瞬間出現。

多年來，變通方法是 JavaScript 的時機技巧：

```js
// 先顯示元素（建立計算狀態）
element.style.display = 'block';
// 在下一個渲染幀添加觸發過渡的 class
requestAnimationFrame(() => element.classList.add('visible'));
```

`requestAnimationFrame` 回呼在瀏覽器以初始狀態繪製元素後觸發，給過渡提供一個「之前」的值進行插值。這雖然有效，但很脆弱：它將原本應屬於純 CSS 的呈現關注點與 JavaScript 耦合在一起，而且時機在技術上取決於各瀏覽器的實作。

Chrome 117 同時引入了兩個相關功能：

1. **`@starting-style`**：一個 at-rule，明確宣告元素首次變為可見時過渡的初始計算值。
2. **可動畫的 `display`**：`display` 屬性現在可以參與 CSS 過渡，讓 `display: none` → `display: block` 成為流暢動畫序列的一部分。

Toast 通知出現時向下滑入並淡入，或對話框以動畫方式開啟，這些效果現在都能用純 CSS 寫成，不需要 JavaScript。下方的〈範例〉以 Popover API 建構對話框案例，Chrome、Firefox、Safari 皆已支援。進場動畫在三者中都能運作；離場時的頂層清理則在 Firefox 和 Safari 中降級，因為這兩者不支援 `overlay`（詳見下文）。〈深入探討〉回到 Toast 案例，其中有一個 Safari 特有的注意事項。

## 視覺對比

核心機制在於：元素變為可見的那一刻，瀏覽器要從哪個計算值開始插值。

| 階段 | 沒有 `@starting-style`（`display: none` → `block`） | 有 `@starting-style` |
|---|---|---|
| 變更前的計算樣式 | 無；不存在盒模型 | 無；不存在盒模型 |
| 瀏覽器插值的起點 | 無。沒有值可以插值，過渡直接跳到終值 | `@starting-style` 內宣告的值（例如 `opacity: 0`） |
| 第一個渲染幀 | 最終狀態，瞬間出現 | `@starting-style` 的狀態 |
| 過渡時間結束時 | 與第一幀相同；沒有發生動畫 | 最終狀態，帶有動畫 |

## 範例

一個使用 Popover API 的對話框，開啟時從上方淡入並向下滑入，關閉時淡出並向上滑出。完整動畫是純 CSS：按鈕上的 `popovertarget` 屬性無需任何 JavaScript 即可處理開啟/關閉。

Popover 與 `<dialog>` 元素渲染在瀏覽器的 *top layer*（頂層），這是一個位於一般文件之上的堆疊上下文，能保證它們無論 z-index 為何都渲染在最上方。CSS `overlay` 屬性控制元素是否屬於這個頂層，它和 `display` 一樣是離散屬性，需要 `allow-discrete` 才能參與過渡。截至 2026-07，`overlay` 僅在 Chrome 與 Edge 中受支援；Firefox 與 Safari 會靜默地將它從過渡清單中移除，這會影響這兩者的離場動畫（詳見下方的步驟說明與〈深入探討〉）。

```html
<button popovertarget="my-dialog">開啟對話框</button>

<div id="my-dialog" class="dialog" popover>
  <p>Hello from the dialog!</p>
  <button popovertarget="my-dialog" popovertargetaction="hide">關閉</button>
</div>
```

```css
/* 基礎佈局 — 永遠套用 */
.dialog {
  padding: 2rem;
  border-radius: 8px;
  border: 1px solid #e2e8f0;
  background: #fff;
  box-shadow: 0 8px 24px rgb(0 0 0 / 0.12);
  max-width: 480px;
  width: 90%;
}

@media (prefers-reduced-motion: no-preference) {
  /* 最終（開啟）狀態 */
  .dialog:popover-open {
    opacity: 1;
    transform: translateY(0);
  }

  /* 過渡宣告——包含 display，讓 popover 在從頂層移除前能夠動畫離場 */
  .dialog {
    transition:
      opacity 0.25s ease,
      transform 0.25s ease,
      display 0.25s allow-discrete,
      overlay 0.25s allow-discrete;
  }

  /* 進場：對話框首次變為可見時的起始狀態 */
  @starting-style {
    .dialog:popover-open {
      opacity: 0;
      transform: translateY(-12px);
    }
  }

  /* 離場：在 display:none 套用之前，向隱藏狀態動畫 */
  .dialog:not(:popover-open) {
    opacity: 0;
    transform: translateY(-12px);
  }
}
```

### 進場的運作方式

當 popover 開啟時：

1. 瀏覽器將 `:popover-open` 套用到對話框，使其成為頂層（top layer）的一部分。
2. 由於 `display: none` → 顯示是帶有 `allow-discrete` 的離散切換，`display` 的切換在過渡開始時立即發生。
3. `@starting-style` 提供初始計算值：`opacity: 0`、`transform: translateY(-12px)`。
4. 過渡在 250 毫秒內從 `@starting-style` 的值插值到 `:popover-open` 的值（`opacity: 1`、`transform: translateY(0)`）。

### 離場的運作方式

當 popover 關閉時：

1. 瀏覽器移除 `:popover-open`，啟用 `:not(:popover-open)` 規則（`opacity: 0`、`transform: translateY(-12px)`）。
2. `display` 過渡（帶有 `allow-discrete`）將該離散切換延遲到最後，使元素在 opacity 與 transform 動畫期間保持可見。`overlay` 過渡對頂層成員資格做同樣的事，但僅限於 Chrome 與 Edge：Firefox 與 Safari 不支援 `overlay` 屬性，因此在這兩個瀏覽器中，頂層可能在 250 毫秒動畫結束前就被移除，導致離場動畫看起來被截斷。詳見〈深入探討〉中關於 `overlay` 的說明。
3. 250 毫秒後（在 `overlay` 能延遲移除的瀏覽器中），過渡結束，頂層成員資格和 `display: none` 套用，元素消失。

### 漸進增強降級

若沒有 `@media (prefers-reduced-motion: no-preference)` 包裹，popover 仍然正確地開啟和關閉，只是不帶動畫地出現和消失。不支援 `@starting-style` 的瀏覽器同樣會直接顯示 popover 而不帶動畫，而不是發生破版，因此嚴格來說不一定需要守衛。

若要更嚴格的漸進增強，請以 `transition-behavior: allow-discrete` 作為守衛條件，而非 `:popover-open`：Popover 在每個引擎中都比 `@starting-style` 更早上線，因此用 `:popover-open` 檢查會產生偽陽性（詳見〈瀏覽器支援〉）。

```css
@supports (transition-behavior: allow-discrete) {
  @media (prefers-reduced-motion: no-preference) {
    /* 動畫規則放在這裡 */
  }
}
```

## 最佳實踐

- MUST 在任何用於動畫元素進場的 `transition` 旁邊加上 `@starting-style`。若沒有它，就沒有起始狀態，過渡在首次渲染或從 `display: none` 切換時不會播放。
- MUST 在過渡 `display` 或 `visibility` 時使用 `allow-discrete` 關鍵字。這些是離散屬性：它們不進行數值插值。`allow-discrete` 旗標告訴瀏覽器：在離場時將離散切換延遲到過渡結束後執行；在進場時立即在開始時執行。語法：`transition: opacity 0.3s, display 0.3s allow-discrete`。
- MUST NOT 將 `@starting-style` 用於離場動畫。它只在元素首次渲染或從 `display: none` 過渡出來時生效。離場動畫應在針對隱藏狀態的選擇器規則中定義目標狀態（例如 `:not(:popover-open)`）。
- SHOULD 將所有進場/離場動畫 CSS 包裹在 `@media (prefers-reduced-motion: no-preference)` 中，以避免對敏感使用者觸發前庭功能障礙（vestibular disorders）。
- SHOULD 在規範允許巢狀的情況下，將 `@starting-style` 巢狀在元素現有的規則區塊內。這讓起始狀態與過渡宣告緊鄰，更易於維護。
- MAY 對新插入 DOM 的元素使用 `@starting-style`，而不僅限於從 `display: none` 過渡的情況。只要元素首次獲得計算樣式，規則就會觸發，不過這個特定路徑在 Safari 17.6 中被回報無法觸發（MDN browser-compat-data issue #25643，截至 2026-07 仍未關閉），在該瀏覽器上應將其視為漸進增強。

## 設計思維

### 為什麼 CSS 過渡過去無法對進場產生動畫

CSS 過渡需要兩個計算樣式快照：變更前的值和變更後的值。瀏覽器擷取「之前」的快照，套用新的 CSS，擷取「之後」的快照，然後在指定持續時間內進行插值。

當元素設定了 `display: none` 時，它完全不在格式化上下文中。`display: none` 的元素沒有渲染出的盒模型，因此瀏覽器沒有為它保留任何可插值的值。`display` 切換為 `block` 的瞬間，瀏覽器從頭建立一個新的布局盒，沒有「之前」的快照，因此不會觸發過渡。

### JavaScript 技巧如何補救

`requestAnimationFrame` 技巧之所以有效，是因為它強迫瀏覽器在添加觸發過渡的 class 之前，提交一個顯示元素初始狀態的渲染幀。初始繪製完成後，「之前」的快照便存在了，過渡就能正常觸發。

其他變通方法包括：

- **使用 `visibility: hidden` 代替 `display: none`**：`visibility` 是可動畫的離散屬性，即使元素隱藏，它仍然保留在布局流中（佔用空間），維持著計算出的盒模型。這解決了過渡問題，但有布局的副作用。
- **搭配 `animation-fill-mode: forwards` 的 `@keyframes` 動畫**：使用 `@keyframes from { opacity: 0 }` 完全繞過過渡問題，因為關鍵幀始終有明確的起始幀。代價是 CSS 更冗長，且與 `transition` 屬性的可組合性較差。
- **雙重 `requestAnimationFrame`**：部分函式庫使用兩個巢狀的 rAF 呼叫，確保在觸發 class 之前有兩個渲染幀，以規避某些瀏覽器的不一致行為。

### 為什麼 `@starting-style` 是正確的模型

`@starting-style` 明確地表達意圖。它直接在 CSS 中回答了一個問題：「這個元素從哪裡開始產生動畫？」不需要依賴繪製時機的巧合或 JavaScript 的協調。瀏覽器的任務變得毫不模糊：使用 `@starting-style` 中的值作為插值起點，然後過渡到元素正常規則中的值。

這也讓程式碼更易於理解：起始狀態、結束狀態和過渡時機都在樣式表中。

## 深入探討

### `@starting-style` 與 Shadow DOM

`@starting-style` 在 shadow root 內部有效。在 shadow tree 內 `<style>` 元素中宣告的規則，在 shadow root 內的元素首次變為可見時套用，遵循與所有其他 Shadow DOM 樣式相同的作用域規則。

### `@starting-style` 只適用於過渡，不適用於 `@keyframes`

`@keyframes` 動畫已經有明確的第一個影格：`from` 或 `0%` 區塊，它們不需要 `@starting-style`。這個 at-rule 只用於為 CSS 過渡提供「之前」的快照。如果你從基於 `transition` 的進場動畫切換到基於 `@keyframes` 的動畫，請移除 `@starting-style`，改在關鍵幀區塊中使用 `from { opacity: 0; transform: translateY(-12px); }`。

一個常見的混淆點：`animation-fill-mode: backwards` 會在動畫開始前填充 `from` 關鍵幀，表面上與 `@starting-style` 為過渡所做的事情相似。兩者是完全無關的機制，`animation-fill-mode` 作用於關鍵幀時間軸，而 `@starting-style` 作用於過渡系統的前後快照模型。

### 將 `@starting-style` 巢狀在選擇器內

規範支援將 `@starting-style` 巢狀在它所套用的規則內：

```css
.dialog:popover-open {
  opacity: 1;
  transform: translateY(0);
  transition: opacity 0.25s, transform 0.25s, display 0.25s allow-discrete;

  @starting-style {
    opacity: 0;
    transform: translateY(-12px);
  }
}
```

這種巢狀形式讓起始狀態與最終狀態及過渡宣告緊鄰在一起。它在效果上等同於非巢狀形式，在 `@starting-style` 支援的所有環境中都有效（Chrome 117+、Firefox 129+、Safari 17.5+）。

### `@starting-style` 內的優先級（Specificity）

`@starting-style` 內的規則與區塊外等效規則的優先級相同。`@starting-style { .dialog:popover-open { opacity: 0; } }` 的優先級就是 `.dialog:popover-open` 的優先級：一個 class 加一個偽類別。這意味著你可以像覆蓋一般 CSS 一樣，用更高優先級的選擇器來覆蓋 `@starting-style` 的值。

### `overlay` 屬性

`overlay` 控制元素是否在瀏覽器的頂層（top layer）。它與 `display` 一樣是離散屬性，也需要 `allow-discrete` 才能參與過渡：

```css
transition: opacity 0.3s, display 0.3s allow-discrete, overlay 0.3s allow-discrete;
```

在過渡中加入 `overlay` 可確保頂層（Popover 和 `<dialog>` 元素所在的背景和堆疊上下文）也能流暢地動畫離場。若不包含它，頂層上下文在關閉時會立即塌陷，可能導致離場動畫被截斷或跳躍。

截至 2026-07，`overlay` 僅在 Chrome 與 Edge 117+ 中受支援。MDN 將它標記為非 Baseline，原因是它在部分主流瀏覽器中無法運作，Firefox 與 Safari 均未實作。在這兩個引擎中，該宣告會從過渡清單中被移除，離場動畫因此失去 `overlay` 原本提供的保護，其被截斷的方式與刻意省略該屬性時相同。請將 `overlay` 視為僅限 Chromium 的增強效果：在支援它的瀏覽器中加入這行宣告，但不要依賴它來保證所有瀏覽器的離場動畫都乾淨俐落。

### `visibility` 與 `display` 的互動

如果你的隱藏狀態使用 `visibility: hidden` 而非 `display: none`，則不需要 `allow-discrete`，因為 `visibility` 已作為可過渡的離散屬性被 CSS 過渡系統處理。對於基於 `visibility` 的顯示/隱藏，嚴格來說也不需要 `@starting-style`，因為 `visibility: hidden` 的元素仍然有計算出的盒模型和屬性值，過渡可以從中開始。`@starting-style` 在 `display: none`、Popover、`<dialog>` 等不存在先前計算狀態的場景中最有價值。

### 對動態插入 DOM 的節點使用 `@starting-style`

`@starting-style` 不僅限於切換 `display` 的元素，它在元素首次插入 DOM 時也會觸發，例如透過 JavaScript 動態建立的 Toast 通知：

```js
const toast = document.createElement('div');
toast.className = 'toast';
toast.textContent = '檔案已儲存。';
document.body.appendChild(toast);
```

```css
.toast {
  position: fixed;
  bottom: 1.5rem;
  right: 1.5rem;
  padding: 0.75rem 1.25rem;
  background: #1e293b;
  color: #fff;
  border-radius: 6px;
  opacity: 1;
  transform: translateY(0);
  transition: opacity 0.3s ease, transform 0.3s ease;
}

@media (prefers-reduced-motion: no-preference) {
  @starting-style {
    .toast {
      opacity: 0;
      transform: translateY(8px);
    }
  }
}
```

元素被附加到 DOM 時，瀏覽器為其指定第一個計算樣式。`@starting-style` 攔截這個時刻，提供 `opacity: 0` 和 `transform: translateY(8px)` 作為起始值。過渡接著從這些值播放到正常規則的值（`opacity: 1`、`translateY(0)`），產生進場動畫，不需要 `requestAnimationFrame`。

離場時，可以命令式地設定 `opacity: 0`（或透過 class），然後監聽 `transitionend` 事件來呼叫 `element.remove()`。

**Safari 注意事項**：根據針對 Safari 17.6 的回報，`@starting-style` 對頁面初次載入時就存在的元素能正確套用，但對之後才插入 DOM 的元素（包括這個 Toast 範例）不會觸發。追蹤此問題的 MDN browser-compat-data issue #25643 截至 2026-07 仍未關閉。Chrome 與 Firefox 沒有這個問題。在 Safari 上，應將 Toast 的進場動畫視為漸進增強：Toast 仍會出現，只是不帶滑入或淡入效果，不會破版，但在此問題尚未解決前，不要依賴這個路徑來實現必要的視覺效果。

### 功能偵測

`@supports at-rule(@starting-style)` 是直接詢問「這個瀏覽器支援 `@starting-style` at-rule 嗎？」的方式。截至 2026-07，這個方法可行：Chrome 與 Edge 148 已於 2026-05-05 將 `at-rule()` 支援推送到穩定版通道。Firefox 與 Safari 尚未實作 `at-rule()`，因此即使這兩個引擎其實已支援 `@starting-style` 本身，這個檢查在它們身上仍會回傳 false；對這兩個引擎而言，仍需要下方其中一種替代偵測方式。

部分教學文章使用的捷徑，是改用 `:popover-open` 選擇器支援作為判斷依據，假設 `@starting-style` 和 Popover API 是同時推出的。事實並非如此。Popover 在每個引擎中都更早上線（Chrome 114、Safari 17.0、Firefox 125），`@starting-style` 則較晚推出（Chrome 117、Safari 17.5、Firefox 129）。落在這段落差區間的瀏覽器，例如 Safari 17.0 到 17.4，會通過 `:popover-open` 檢查，卻不支援 `@starting-style`，因此這個守衛在該區間會是偽陽性。

`transition-behavior: allow-discrete` 是更接近的替代偵測方式。它與 `@starting-style` 在 Chrome 和 Firefox 中於相同版本上線，在 Safari 中也只早了一個小版本（17.4 對 17.5）：

```css
@supports (transition-behavior: allow-discrete) {
  /* @starting-style 與 allow-discrete 過渡 */
}
```

```js
const supported = CSS.supports('transition-behavior', 'allow-discrete');
```

這個方法在 Safari 17.4 上仍有一個狹窄的偽陽性區間，但比 popover 檢查緊密得多。對於尚未實作 `at-rule()` 的引擎（截至 2026-07 的 Firefox 與 Safari），Bram.us 文件記錄的 Space Toggle 技巧（見〈參考資料〉）是進一步的備援方案，能在不依賴共同上線特性的情況下偵測 `@starting-style` 支援。

不支援 `@starting-style` 的瀏覽器會靜默跳過起始狀態區塊。進場過渡不會播放，元素直接以最終狀態瞬間出現，而不會發生破版。

Internet Explorer 和舊版 Edge（Chromium 之前）不支援 `@starting-style`。這些瀏覽器已超出大多數新專案的支援範圍，但如果你的目標包含它們，請將所有進場動畫視為純裝飾性效果，並確保元素在沒有動畫的情況下，預設 CSS 狀態是完全可見的。
