# [FEE-11001] CSS Anchor Positioning — 錨點定位

:::info
使用純 CSS 將任何浮動覆蓋層（工具提示、下拉選單、popover）繫結至頁面上的任意元素，具備自動溢出重定位功能，完全不需要 JavaScript。
:::

:::info Baseline Newly Available
Supported in Chrome 125+, Firefox 130+, Safari 18.4+. Use progressive enhancement for older browsers.
:::

## 背景

每位曾經建立工具提示、下拉選單或右鍵選單的開發者都遇過同樣的困境：CSS `position: absolute` 會相對於最近的*定位祖先*（positioned ancestor）來計算偏移量，而非相對於 DOM 樹中任意的兄弟或表親元素。錨點元素與浮動覆蓋層往往存在於不同的堆疊上下文（stacking context）、不同的捲動容器，或單純處於不同的巢狀深度。

傳統的解決方案是 JavaScript：

1. 以 `getBoundingClientRect()` 讀取錨點元素的位置。
2. 計算覆蓋層應該放置的位置。
3. 以命令式（imperatively）設定 `top` 和 `left`。
4. 接上 `ResizeObserver` 和捲動事件監聽器，以保持同步。
5. 在每次 resize 和裝置方向改變時重複以上步驟。

Popper.js 和 Floating UI 等函式庫多年來可靠地解決了這個問題，但它們增加了傳輸量、需要在 UI 正確顯示之前解析並執行 JavaScript，且在第一次繪製（paint）前的定位計算完成之前，可能會出現短暫的錯位閃爍（FOMC，flash of mispositioned content）。

CSS Anchor Positioning 將所有這些工作移入瀏覽器的版面計算引擎（layout engine）。瀏覽器在處理所有其他幾何運算的同一次版面計算中，同時計算錨點位置——在繪製之前，而非之後。不需要 `ResizeObserver` 迴圈，不需要捲動監聽器，定位本身完全不需要 JavaScript。

## 情境

你正在程式碼區塊內建立一個「複製到剪貼簿」按鈕。當使用者點擊時，一個小型「已複製！」工具提示應出現在按鈕上方。若按鈕靠近視口頂端，工具提示應自動翻轉到按鈕下方，而不是溢出螢幕外。工具提示使用 Popover API 以確保無障礙性（accessibility）。

使用傳統 CSS，你需要 JavaScript 來測量按鈕位置並以命令式撰寫 `top`/`left` 樣式。使用 CSS Anchor Positioning，包含溢出回退（overflow fallback）的整個定位關係都可以用 CSS 宣告式描述。

## 最佳實踐

- MUST 為任何可能出現在螢幕邊緣附近的錨點定位元素定義 `position-try-fallbacks`。沒有回退方案，覆蓋層將會被裁切或溢出視口。
- SHOULD 將 CSS Anchor Positioning 與 Popover API 搭配使用，免費獲得無障礙焦點管理（focus management）和鍵盤關閉功能，不需要額外 JavaScript。
- MUST NOT 將 CSS Anchor Positioning 用於文件版面——區塊元素、格線軌道或頁面結構。此功能專為浮動在正常流（normal flow）之上的覆蓋層而設計。
- 在觸發覆蓋層的互動元素（按鈕、連結或輸入框）上使用 `anchor-name`，而非包裝用的 `<div>`。這使錨點在語意上與使用者互動的元素保持關聯。
- MUST 採用漸進增強（progressive enhancement）。將錨點定位屬性包在 `@supports (anchor-name: --x)` 區塊中，使舊版瀏覽器能夠回退到靜態或 JavaScript 驅動的定位，而非破損的版面。
- 在列表或重複元件中，使用 `anchor-scope` 防止 `anchor-name` 值洩漏到其他列表項目，並意外指向錯誤的錨點。

## 設計思維

### 為何需要 JavaScript

CSS 中的 `position: absolute` 會相對於元素的*包含區塊*（containing block）解析偏移量，即最近的 `position` 非 `static` 的祖先元素（或視口的初始包含區塊）。CSS 沒有任何機制可以說「相對於這個特定兄弟元素做偏移」——CSS 在此之前從未有過跨元素的幾何參考機制。

當 `position: absolute` 不夠用時，開發者有兩個傳統選項：

- **重構 DOM** 使覆蓋層成為錨點的子元素。但若錨點位於 `overflow: hidden`、CSS `transform` 或 `will-change` 上下文中，這樣做將失效——這些都會建立新的堆疊和包含區塊上下文。
- **JavaScript 測量**，透過 `getBoundingClientRect()`，雖然有效但每次捲動、resize 和方向改變時都需要重新計算。

### Popper.js 與 Floating UI 的解決方式

兩個函式庫都遵循相同模式：開啟時讀取錨點的 `DOMRect`，進行幾何運算，以計算出的 `top`/`left` 設定 `position: fixed` 或 `position: absolute`。它們使用 `ResizeObserver` 偵測尺寸變化，並使用被動捲動監聽器（passive scroll listeners）在捲動時重新計算。結果是正確的定位，但代價是 JavaScript 和瀏覽器版面引擎之間的同步迴圈。

錯位閃爍之所以發生，是因為 JavaScript 在瀏覽器已完成繪製之後才執行。元素首先在其預設位置渲染，然後 JavaScript 移動它，然後瀏覽器再次重繪。

### 原生 CSS 為何更好

CSS Anchor Positioning 在瀏覽器的版面引擎內部運行，在解析所有其他幾何運算的同一次計算中進行。這意味著：

- **無 FOMC**：定位元素在第一次繪製前就被正確放置。
- **無 ResizeObserver**：瀏覽器已將元素尺寸追蹤作為版面計算的一部分——不需要獨立的 JavaScript 觀察迴圈。
- **自動捲動追蹤**：錨點定位元素在捲動時跟隨其錨點移動，不需要任何 `scroll` 事件監聽器。
- **宣告式溢出處理**：`position-try-fallbacks` 在 CSS 中編碼所有替代位置。瀏覽器自動選擇最合適的方案。

權衡之處在於 CSS Anchor Positioning 只適用於 `position: absolute` 或 `position: fixed` 的元素——它不適用於正常流中的元素。

## 範例

一個「複製」按鈕，其工具提示預設出現在按鈕上方，當按鈕靠近視口頂端時自動重定位到下方。

```html
<div class="code-block">
  <pre><code>const x = 1;</code></pre>
  <button class="copy-btn" id="copy-btn" popovertarget="copy-tooltip">
    Copy
  </button>
  <div id="copy-tooltip" class="tooltip" popover>Copied!</div>
</div>
```

```css
/* Fallback for unsupported browsers */
.tooltip {
  position: fixed;
  top: 50%;
  left: 50%;
  transform: translate(-50%, -50%);
}

/* Anchor positioning where supported */
@supports (anchor-name: --x) {
  .copy-btn {
    anchor-name: --copy-btn;
  }

  .tooltip {
    position: absolute;
    position-anchor: --copy-btn;
    position-area: top center;
    position-try-fallbacks: flip-block;
    margin: 8px;
    /* reset the fallback fixed positioning */
    top: unset;
    left: unset;
    transform: none;
  }
}
```

### 說明

- 觸發按鈕上的 `popovertarget="copy-tooltip"` 屬性，搭配按鈕本身的 `id="copy-btn"`，讓瀏覽器得以解析隱式錨點關係——CSS 中的 `position-anchor` 屬性可以直接參考此關係，無需重複 CSS 的 `anchor-name`。
- `position-area: top center` 將工具提示置於按鈕上方，水平置中。
- `position-try-fallbacks: flip-block` 告訴瀏覽器：若偏好位置溢出視口，則在塊軸（block axis）嘗試鏡像位置（即從上方切換為下方，或反之）。若需要更複雜的多步驟回退，請定義具名的 `@position-try` 區塊。
- `@supports (anchor-name: --x)` 區塊使用最佳實踐中建議的正向形式，僅在支援的瀏覽器中套用錨點定位，區塊外的回退固定定位則處理舊版瀏覽器。

## 深入探討

### `inset-area` 重新命名

早期草稿與 Chrome 125–128 版本使用屬性名稱 `inset-area`。CSS 工作小組在 Chrome 129 中將其重命名為 `position-area`（已出貨）。若你在較舊的文件或教學中遇到 `inset-area`，請將其視為同一個屬性。兩個名稱指的是相同的格線式定位（grid-based positioning）簡寫；`position-area` 是目前的正式名稱。

同樣地，`position-try-options` 是 `position-try-fallbacks` 的早期名稱。只有 `position-try-fallbacks` 是目前正確的用法。

### `anchor()` 函式

若要精確的邊對邊定位，使用 `anchor()` 函式取代 `position-area`：

```css
.tooltip {
  position: absolute;
  position-anchor: --copy-btn;

  /* 工具提示左邊緣 = 錨點右邊緣 */
  left: anchor(right);

  /* 工具提示上邊緣 = 錨點下邊緣 */
  top: anchor(bottom);
}
```

`anchor()` 接受邊側關鍵字：`top`、`right`、`bottom`、`left`、`start`、`end`、`self-start`、`self-end`、`center` 或百分比。這讓你能精確控制定位元素的哪條邊對齊錨點的哪條邊。

### `anchor-size()` 函式

若要相對於錨點調整覆蓋層大小：

```css
.dropdown {
  position: absolute;
  position-anchor: --trigger;

  /* 完全符合錨點寬度 */
  width: anchor-size(width);

  /* 或以錨點寬度為上限 */
  max-width: anchor-size(width);
}
```

`anchor-size()` 接受 `width`、`height`、`block`、`inline`、`self-block` 或 `self-inline`。

### 使用 `@position-try` 建立具名回退規則

對於涉及不只是不同 `position-area` 的複雜回退，使用 `@position-try` 定義具名規則集：

```css
@position-try --flip-below {
  position-area: bottom center;
  margin-top: 8px;
  margin-bottom: 0;
}

@position-try --flip-right {
  position-area: right span-top;
  margin-left: 8px;
}

.tooltip {
  position: absolute;
  position-anchor: --copy-btn;
  position-area: top center;
  margin-bottom: 8px;

  /* 依序嘗試具名回退 */
  position-try-fallbacks: --flip-below, --flip-right;
}
```

瀏覽器依序嘗試每個回退，並使用第一個使定位元素完全符合其捲動容器的方案。

### 隱式錨點

若 popover 透過 `popovertarget` / `id` 屬性與其觸發器關聯，觸發器自動成為 popover 的隱式錨點。在這種情況下，CSS 中的 `position-anchor` 可以省略：

```css
/* 當 HTML 錨點關聯已設定時，此寫法有效 */
.tooltip {
  position: absolute;
  position-area: top center;
  position-try-fallbacks: flip-block;
}
```

仍建議明確宣告 `position-anchor`，特別是當 CSS 單獨閱讀時，以提高可讀性。

### 與 `overflow: hidden` 的互動

錨點定位是相對於包含錨點的*捲動容器*（scroll container）解析，而非 CSS 包含區塊。這意味著覆蓋層可以逸出帶有 `overflow: hidden` 的父元素，前提是該父元素不是捲動容器。但若覆蓋層離開最近的捲動容器，仍然會被裁切——它不會自動逸出到視口，除非使用 `position: fixed`。

對於必須逸出所有溢出限制的工具提示，使用 `position: fixed` 搭配錨點定位。`position: fixed` 使捲動容器成為視口，而錨點定位仍然正常運作。

### `anchor-scope`

在列表或重複元件中，多個元素可能共享相同的 `anchor-name` 值。預設情況下，定位元素會找到 DOM 順序中*最後一個*具有相符名稱的錨點，這幾乎不是列表場景中你想要的行為。

`anchor-scope` 將可參考特定 `anchor-name` 的定位元素限制在一個子樹範圍內：

```css
.list-item {
  /* 限定範圍，使此項目中的錨點只匹配此項目內的 popover */
  anchor-scope: --item-anchor;
}

.list-item .trigger {
  anchor-name: --item-anchor;
}

.list-item .menu {
  position: absolute;
  position-anchor: --item-anchor;
  position-area: bottom span-right;
}
```

`anchor-scope` 接受單一 `<dashed-ident>` 或關鍵字 `all`。使用 `all` 可將子樹中宣告的所有 `anchor-name` 一次限定範圍，對於定義了許多錨點的複雜元件樹來說，是一個方便的全面防護。

注意 `anchor-scope` 只影響名稱解析，不影響溢出或包含行為。

### 常見錯誤

**在視口邊緣附近忘記設定 `position-try-fallbacks`。**
未設定回退方案的錨點定位工具提示，在錨點靠近視口上下左右邊緣時將溢出或被裁切。對垂直擺放的覆蓋層，至少宣告 `position-try-fallbacks: flip-block`；對水平擺放的，使用 `flip-inline`。

**將 `anchor-name` 套用在包裝用的 `<div>` 而非互動元素上。**
螢幕閱讀器和鍵盤導覽預期互動元素（按鈕、連結、輸入框）與其覆蓋層之間存在無障礙關聯。將 `anchor-name` 放在非互動的祖先元素上會切斷這層關聯。

**將 CSS Anchor Positioning 用於正常流版面。**
`position-area` 和 `anchor()` 等屬性只對 `position: absolute` 或 `position: fixed` 的元素有效。將它們套用在正常流中的區塊級元素上不會產生任何效果，也會誤導閱讀 CSS 的人。

**誤以為必須用 `position: fixed` 才能逸出 `overflow: hidden`。**
`position: fixed` 確實有效，但它同時將元素從捲動容器的座標系中移除，可能導致覆蓋層在頁面捲動時無法跟隨錨點。應優先使用 `position: absolute`，除非明確需要相對視口的定位；先確認 `overflow: hidden` 的祖先是否為捲動容器——若不是，`position: absolute` 本身就能逸出它。

**省略 `@supports` 包裝。**
沒有功能偵測，錨點定位屬性在舊版瀏覽器中會靜默忽略——但若你忘記重設，`@supports` 區塊內的屬性可能覆蓋你在外部設定的回退樣式。請始終在 `@supports` 區塊之外搭配一個回退方案。

使用 `@supports` 的漸進增強模式：

```css
@supports (anchor-name: --x) {
  /* 錨點定位樣式 */
}
```

或在 JavaScript 中進行功能偵測，以決定是否啟用覆蓋層函式庫：

```js
const supportsAnchorPositioning =
  CSS.supports('anchor-name', '--x');
```
