# [FEE-11103] View Transitions — 第一層級

:::info
在任何元素上宣告一個 CSS 屬性，再用一個函式呼叫包裝 DOM 變更，瀏覽器就會自動處理截圖擷取、動畫播放與 DOM 切換——不需要 JavaScript 協調邏輯，不產生競態條件。
:::

:::info Baseline Newly Available
Supported in Chrome 111+, Firefox 144+, Safari 18+. May not yet be safe for all production use without progressive enhancement.
:::

## 背景

單頁應用程式需要在視圖之間播放動畫。當使用者點擊縮圖並期望它「變形」為全尺寸的主角圖片，或者路由切換時應該以滑入而非直接切換的方式呈現，開發者必須協調多個非同步操作而不讓它們產生競態。

最直覺的做法需要四個同步的步驟：

1. 擷取離場內容的截圖。
2. 在截圖上啟動動畫，讓舊內容看起來正在淡出。
3. 將 DOM 切換為新狀態。
4. 將進場內容動畫到其最終位置。

在實作中，步驟 3 是非同步的——新狀態可能依賴路由切換、狀態更新或 React 重新渲染。步驟 1 和步驟 3 必須同步：若 DOM 在截圖完成之前就切換了，快照會擷取到錯誤的狀態；若截圖太晚，使用者會在動畫開始前看到未樣式化的閃爍。

共享元素過渡讓問題更加複雜。當縮圖應該「變形」為主角圖片時，開發者必須：

- 在 DOM 更新之前記錄縮圖的邊界框。
- 在 DOM 更新之後記錄主角圖片的邊界框。
- 計算兩者之間的差值（位置偏移與縮放變化）。
- 使用 CSS transform 套用 FLIP 動畫（First、Last、Invert、Play），讓元素看起來從舊位置移動到新位置。
- 確保元素被正確合成，在過渡期間渲染在離場和進場內容的上方。

現有函式庫解決了部分問題。Framer Motion 的 `AnimatePresence` 元件處理掛載/卸載動畫，但需要包裝元件樹並引入執行期相依性。GSAP Flip 外掛提供位置差值計算，但需要學習獨立的 API，且仍依賴 JavaScript 來正確計時 DOM 切換。Swup.js 增加了頁面過渡協調功能，但架構上綁定於整頁切換，而非元件層級的共享元素。所有這些方法對於精緻的過渡都需要 80–200+ 行程式碼。

View Transition API 從根本原因著手：瀏覽器本身擷取 before 快照，在回呼中原子性地執行 DOM 更新，擷取 after 快照，然後在兩者之間播放動畫。排序由平台保證，而非 JavaScript 計時。

## 情境

你正在建立一個相片集 SPA。圖庫視圖顯示縮圖格格。點擊縮圖應該顯示選中相片的全尺寸詳細視圖，且縮圖應該視覺上變形為主角圖片——流暢地放大和重新定位，而非直接切換到下一個視圖。

需求如下：

- 從圖庫到詳細視圖的過渡：縮圖縮放並移動變為主角圖片。
- 返回時：反向變形，主角圖片縮小並返回縮圖位置。
- 不需要 JavaScript FLIP 計算。
- 不需要第三方動畫函式庫。
- 不支援 View Transition 的瀏覽器獲得即時切換（優雅降級）。
- 設定 `prefers-reduced-motion: reduce` 的使用者不播放動畫。

使用 View Transition API，兩個過渡都只需要一個 `document.startViewTransition()` 呼叫，以及在共享元素上設定 `view-transition-name` CSS 屬性。

## 最佳實踐

- MUST 將所有 DOM 變更放在 `startViewTransition` 回呼內。在回呼外發生的變更——呼叫之前或之後——不會被 before/after 快照機制擷取。瀏覽器在回呼執行前立即取 "before" 快照，在回呼返回的 Promise 解析後取 "after" 快照。在此窗口外進行的任何 DOM 變更對過渡系統都是不可見的。

- SHOULD 為每個共享元素賦予唯一的 `view-transition-name`。`view-transition-name` 屬性指示瀏覽器將元素視為命名快照參與者——它為該元素擷取獨立的 before/after 快照對，並將其獨立於根部交叉淡入淡出進行變形。若兩個同時可見的元素共享相同的 `view-transition-name`，瀏覽器會收到模糊信號並產生損壞或缺失的快照。名稱在快照時所有可見元素中必須是唯一的。一個常見錯誤是對列表中的每個項目套用相同的名稱；名稱應標識參與當前過渡的特定元素。

- SHOULD 始終使用 `@media (prefers-reduced-motion: reduce)` 進行測試，並為請求過的使用者停用或縮減過渡。瀏覽器的預設交叉淡入淡出很細膩，有些開發者因此跳過這個步驟，但套用在 `::view-transition-old` 和 `::view-transition-new` 上的自定義 keyframe 動畫可能足夠劇烈到引發前庭症狀。建議模式如下：

  ```css
  @media (prefers-reduced-motion: reduce) {
    ::view-transition-old(*),
    ::view-transition-new(*),
    ::view-transition-group(*) {
      animation: none;
    }
  }
  ```

- SHOULD 始終提供功能偵測備援方案。`document.startViewTransition` 在不支援 API 的瀏覽器上是 undefined。在呼叫之前進行檢查：

  ```js
  if (!document.startViewTransition) {
    updateDOM(); // 即時切換，無過渡
    return;
  }
  document.startViewTransition(() => updateDOM());
  ```

- MAY 在共享元素上使用 `contain: layout` 以防止佈局副作用。命名的 view-transition 元素在過渡期間被提升到自己的合成層；套用 `contain: layout` 可防止它在移動或縮放時影響周圍元素的佈局。

- MAY 獨立自定義 `::view-transition-old` 和 `::view-transition-new` 以建立非對稱的進出場動畫。例如，離場內容可以淡出並向上滑動，而進場內容則從下方淡入——對每個偽元素使用不同的 `@keyframes`。

- SHOULD NOT 一次動態地將 `view-transition-name` 指派給許多元素。每個命名元素都會使瀏覽器擷取額外的 GPU 紋理快照。在過渡前將名稱指派給列表中的所有 50 個項目，會建立 50 個額外的 GPU 層，很可能在過渡開始時造成掉幀。請只將名稱指派給參與當前過渡的一個元素，並在之後移除。

## 設計思維

### 為什麼 JavaScript 協調的過渡很脆弱

根本問題是 JavaScript 沒有「立即擷取當前繪製截圖」的鉤子。最接近的近似是 `html2canvas` 或在前後使用 `element.getBoundingClientRect()`，但兩者都無法擷取實際的像素內容。即使截圖是可能的，「擷取截圖」、「啟動動畫」、「切換 DOM」和「開始進場動畫」之間的時機也必須透過 `requestAnimationFrame`、`setTimeout` 或 `transitionend` 事件協調——所有這些都會引入時機差距，使半切換狀態閃爍給使用者看。

GSAP Flip 解決了部分問題，透過記錄 DOM 更新前後的元素位置並自動計算 CSS transform 差值。但 GSAP Flip 仍需要開發者在 GSAP 管理的回呼中手動觸發 DOM 變更，且使用 CSS transform 而非真正的合成快照來動畫化——這意味著元素的內容在動畫期間是即時的（非凍結的）。若元素的內容在過渡期間發生變化，動畫從第 0 幀就使用新內容，而非從舊內容動畫過渡。

### 瀏覽器的快照模型如何消除競態

`document.startViewTransition(callback)` 提供了有保證的排序契約：

1. 瀏覽器暫停渲染。
2. 它擷取所有命名元素和根部的當前繪製作為 "before" 快照。
3. 它呼叫回呼並等待其返回的 Promise 解析。
4. 它擷取回呼後的繪製作為 "after" 快照。
5. 它恢復渲染並開始在快照之間播放動畫。

因為瀏覽器控制步驟 2 和步驟 4，快照保證彼此一致。從渲染管線的角度來看，「擷取截圖」和「切換 DOM」是原子性執行的，不存在競態條件。

快照是真正的合成像素擷取，而非即時的 DOM 樹。在動畫期間，`::view-transition-old(name)` 是元素之前外觀的凍結圖像，`::view-transition-new(name)` 是之後外觀的凍結圖像。兩者都不是即時元素——它們在動畫期間不會改變。這就是為什麼即使底層 DOM 已完全改變，view transitions 看起來仍然流暢。

### 第一層級與第二層級的差異

View Transition API 分為兩個層級：

**第一層級**涵蓋同文件過渡——由單一頁面內 JavaScript 觸發的過渡。入口點是 `document.startViewTransition()`，這是一個 JavaScript API。第一層級就是本文所涵蓋的內容。它需要開發者明確呼叫 `startViewTransition` 並將 DOM 變更放在回呼中。

**第二層級**涵蓋跨文件過渡——在多頁應用程式（MPA）中不同頁面 URL 之間的過渡，瀏覽器導航到新文件。這完全不需要 JavaScript：瀏覽器偵測到 `@view-transition { navigation: auto; }` CSS 規則，並自動將導航包裝在快照機制中。第二層級在 FEE-11104 中說明。

### 偽元素樹

當 view transition 執行時，瀏覽器在文件上方建立一個臨時的偽元素覆蓋層：

```
::view-transition
  ::view-transition-group(root)
    ::view-transition-image-pair(root)
      ::view-transition-old(root)
      ::view-transition-new(root)
  ::view-transition-group(hero-photo)
    ::view-transition-image-pair(hero-photo)
      ::view-transition-old(hero-photo)
      ::view-transition-new(hero-photo)
```

`::view-transition` 是位於所有文件內容上方的全頁覆蓋層，過渡完成後被移除。

`::view-transition-group(name)` 是定位在 "before" 邊界的包裝元素，動畫到 "after" 邊界。這就是產生共享元素位置和尺寸變形的原因——群組本身在兩個邊界框之間平移和縮放。

`::view-transition-image-pair(name)` 包含兩個快照圖像，並處理它們之間的交叉淡入淡出。

`::view-transition-old(name)` 是 before 快照圖像，預設淡出。

`::view-transition-new(name)` 是 after 快照圖像，預設淡入。

要自定義動畫，可用 `@keyframes` 針對這些偽元素：

```css
@keyframes slide-out-left {
  to { transform: translateX(-100%); opacity: 0; }
}
@keyframes slide-in-right {
  from { transform: translateX(100%); opacity: 0; }
}

::view-transition-old(root) {
  animation: slide-out-left 0.35s ease-in forwards;
}
::view-transition-new(root) {
  animation: slide-in-right 0.35s ease-out forwards;
}
```

### 為什麼預設是交叉淡入淡出

預設過渡是整個頁面根部的 300ms 不透明度交叉淡入淡出。這是有意為之的：交叉淡入淡出是最普遍中性的過渡——它在任意兩個狀態之間都有效，不需要了解佈局，也不需要對方向做假設。更具體的過渡（滑動、變形、揭示）需要開發者透過命名元素和自定義 keyframe 來表達意圖。

## 範例

一個相片集 SPA，點擊縮圖時使用共享元素變形動畫過渡到全尺寸主角視圖。

```html
<div class="gallery" id="gallery">
  <img class="thumb" src="photo-1.jpg" alt="Photo 1" onclick="showDetail(this)">
  <img class="thumb" src="photo-2.jpg" alt="Photo 2"
       onclick="showDetail(this)">
  <img class="thumb" src="photo-3.jpg" alt="Photo 3"
       onclick="showDetail(this)">
</div>
<div class="detail" id="detail" hidden>
  <img class="hero" id="hero-img" src="photo-1.jpg" alt=""
       style="view-transition-name: hero-photo">
  <button onclick="closeDetail()">返回圖庫</button>
</div>
```

注意：只有當前點擊的縮圖和主角圖片共享 `hero-photo` 過渡名稱。在任何時刻只有其中一個是可見的，確保不會發生名稱衝突。

```css
.thumb {
  width: 150px;
  aspect-ratio: 1;
  object-fit: cover;
  cursor: pointer;
  border-radius: 4px;
}

.hero {
  width: 100%;
  max-width: 600px;
  aspect-ratio: 4 / 3;
  object-fit: cover;
  border-radius: 8px;
  display: block;
  margin: 0 auto;
}

/* 自定義根部過渡持續時間 */
::view-transition-old(root),
::view-transition-new(root) {
  animation-duration: 0.4s;
}

/* 為偏好減少動態效果的使用者停用所有 view transition */
@media (prefers-reduced-motion: reduce) {
  ::view-transition-old(*),
  ::view-transition-new(*),
  ::view-transition-group(*) {
    animation: none;
  }
}
```

```js
function showDetail(thumb) {
  // 優雅降級：不支援的瀏覽器即時切換
  if (!document.startViewTransition) {
    document.getElementById('gallery').hidden = true;
    document.getElementById('detail').hidden = false;
    return;
  }

  // 過渡前：將 view-transition-name 指派給被點擊的縮圖，
  // 使其參與共享元素變形
  thumb.style.viewTransitionName = 'hero-photo';

  document.startViewTransition(() => {
    // DOM 變更放在回呼內
    document.getElementById('gallery').hidden = true;
    document.getElementById('detail').hidden = false;

    // 更新主角圖片來源以符合被點擊的縮圖
    document.getElementById('hero-img').src = thumb.src;
    document.getElementById('hero-img').alt = thumb.alt;
  });

  // 過渡開始後，從縮圖移除名稱，
  // 以免圖庫再次顯示時產生衝突
  thumb.style.viewTransitionName = '';
}

function closeDetail() {
  if (!document.startViewTransition) {
    document.getElementById('detail').hidden = true;
    document.getElementById('gallery').hidden = false;
    return;
  }

  document.startViewTransition(() => {
    document.getElementById('detail').hidden = true;
    document.getElementById('gallery').hidden = false;
  });
}
```

### 變形的運作方式

呼叫 `showDetail()` 時：

1. 瀏覽器擷取 `hero-photo` 的 "before" 快照（縮圖在其小尺寸位置）以及 `root`（完整頁面）。
2. 回呼執行：圖庫被隱藏，詳細視圖被顯示，主角圖片來源被更新。
3. 瀏覽器擷取 `hero-photo` 的 "after" 快照（主角圖片在其大尺寸位置）以及 `root`。
4. `::view-transition-group(hero-photo)` 將其位置和尺寸從縮圖邊界動畫到主角圖片邊界。
5. 在群組內，`::view-transition-old(hero-photo)`（縮圖快照）交叉淡入淡出到 `::view-transition-new(hero-photo)`（主角快照）。
6. 同時，`::view-transition-old(root)`（圖庫）淡出，`::view-transition-new(root)`（詳細視圖）淡入。

結果是流暢的變形：縮圖看起來在擴大並移動到主角圖片位置，同時周圍內容交叉淡入淡出。

### 自定義主角變形動畫

預設情況下，變形是交叉淡入淡出加上尺寸/位置插值。若要讓圖片立即呈現完全不透明（只顯示尺寸/位置補間而無不透明度變化）：

```css
::view-transition-old(hero-photo) {
  animation: none;
  opacity: 0; /* 立即隱藏舊快照 */
}
::view-transition-new(hero-photo) {
  animation: none;
  opacity: 1; /* 立即顯示新快照 */
}
```

套用這些規則後，`::view-transition-group(hero-photo)` 仍然動畫化位置和尺寸，但內部圖片不淡入淡出——從第一幀就顯示新的全尺寸圖片，從主角位置縮放到縮圖位置。這產生「縮放」感而非「交叉淡入淡出」感。

### 非對稱進出場

用於基於滑動的頁面過渡（從右側進入，向左側退出）：

```css
@keyframes slide-from-right {
  from {
    transform: translateX(30px);
    opacity: 0;
  }
}

@keyframes slide-to-left {
  to {
    transform: translateX(-30px);
    opacity: 0;
  }
}

::view-transition-old(root) {
  animation: slide-to-left 0.3s ease-in forwards;
}

::view-transition-new(root) {
  animation: slide-from-right 0.3s ease-out forwards;
}

@media (prefers-reduced-motion: reduce) {
  ::view-transition-old(*),
  ::view-transition-new(*),
  ::view-transition-group(*) {
    animation: none;
  }
}
```

### 使用 ViewTransition Promise API

`document.startViewTransition()` 返回一個帶有三個 Promise 的 `ViewTransition` 物件：

```js
const transition = document.startViewTransition(() => updateDOM());

// DOM 更新完成且快照已取得時解析
transition.updateCallbackDone.then(() => {
  console.log('DOM 已更新');
});

// 偽元素建立完成且動畫即將開始時解析
// 使用此 Promise 以程式方式取消或跳過動畫
transition.ready.then(() => {
  console.log('動畫開始');
});

// 過渡動畫完成且偽元素被移除時解析
transition.finished.then(() => {
  console.log('過渡完成');
});
```

`ready` Promise 特別適合在偽元素上觸發 Web Animations API 動畫——例如沿路徑動畫，或使用純 CSS 無法表達的彈簧物理模型。

## 瀏覽器支援

| 瀏覽器  | 同文件 View Transitions | 備注 |
|---------|------------------------|------|
| Chrome  | 111                    | 首個實作 |
| Edge    | 111                    | 基於 Chromium |
| Firefox | 144                    | Firefox 144 推出 |
| Safari  | 18                     | iOS Safari 18 亦支援 |

功能偵測：

```js
if (document.startViewTransition) {
  // 支援 View Transitions 第一層級
}
```

或透過 CSS（主要用於跨文件第二層級，但也可用於文件同文件支援的功能查詢）：

```css
@supports (view-transition-name: none) {
  /* 支援 View Transitions */
}
```

漸進增強模式——始終為不支援的瀏覽器提供即時切換備援，並為偏好減少動態效果的使用者停用動畫。兩個檢查是獨立的，應同時存在。

同文件 view transitions 在 2025 年成為 Baseline Newly Available，意味著三大主要瀏覽器引擎都已支援。跨文件（第二層級）過渡的支援範圍較窄——詳見 FEE-11104。
