# [FEE-11103] View Transitions — 第一層級

:::info
在元素上宣告 `view-transition-name` CSS 屬性，並將 DOM 變更包在 `document.startViewTransition()` 中，瀏覽器就會自動擷取變更前的截圖、執行切換、擷取變更後的截圖，並在兩者之間播放動畫。JavaScript 不必再手動安排截圖、切換與動畫啟動的時機。
:::

:::info Baseline Newly Available
支援 Chrome 111+、Firefox 144+、Safari 18+。若未搭配漸進增強，可能尚不適合用於所有正式環境。
:::

## 背景

單頁應用程式需要在視圖之間播放動畫：點擊縮圖後應變形為全尺寸主角圖片，或路由切換時應將新視圖滑入畫面。要讓這個過程順暢，需要執行多個非同步操作，且不能讓它們產生競態。

最直覺的做法需要四個同步的步驟：

1. 擷取離場內容的截圖。
2. 在截圖上啟動動畫，讓舊內容看起來正在淡出。
3. 將 DOM 切換為新狀態。
4. 將進場內容動畫到其最終位置。

在實作中，步驟 3 是非同步的：新狀態可能依賴路由切換、狀態更新或 React 重新渲染。步驟 1 和步驟 3 必須同步：若 DOM 在截圖完成之前就切換了，快照會擷取到錯誤的狀態；若截圖太晚，使用者會在動畫開始前看到未樣式化的閃爍。

共享元素過渡讓問題更加複雜。當縮圖應該「變形」為主角圖片時，開發者必須：

- 在 DOM 更新之前記錄縮圖的邊界框。
- 在 DOM 更新之後記錄主角圖片的邊界框。
- 計算兩者之間的差值（位置偏移與縮放變化）。
- 使用 CSS transform 套用 FLIP 動畫（First、Last、Invert、Play），讓元素看起來從舊位置移動到新位置。
- 確保元素被正確合成，在過渡期間渲染在離場和進場內容的上方。

現有函式庫解決了部分問題。Framer Motion 的 `AnimatePresence` 元件處理掛載/卸載動畫，但需要包裝元件樹並引入執行期相依性。GSAP Flip 外掛提供位置差值計算，但需要學習獨立的 API，且仍依賴 JavaScript 來正確計時 DOM 切換。Swup.js 增加了頁面過渡協調功能，但其架構圍繞整頁切換設計，並未處理元件層級的共享元素。Astro 的 `<ClientRouter />`（前身為 `<ViewTransitions />`）最接近下文描述的平台行為：它會自動將導航包在 `document.startViewTransition()` 中，但它仍是框架專屬的路由器，而非任何技術棧都能使用的瀏覽器原生機制。

View Transition API 從根本原因著手：瀏覽器本身擷取 before 快照，在回呼中原子性地執行 DOM 更新，擷取 after 快照，然後在兩者之間播放動畫。瀏覽器會自行安排截圖與 DOM 切換的順序，因此 JavaScript 不需要為兩者計時。

本文其餘部分都圍繞同一個範例展開：一個相片集單頁應用程式。圖庫視圖顯示縮圖網格；點擊縮圖會顯示選中相片的全尺寸詳細視圖，且縮圖會隨著視圖切換視覺上變形為主角圖片，逐漸放大並重新定位。

這個範例必須滿足六項需求：

- 從圖庫到詳細視圖的過渡：縮圖縮放並移動變為主角圖片。
- 返回時：反向變形，主角圖片縮小並返回縮圖位置。
- 不需要 JavaScript FLIP 計算。
- 不需要第三方動畫函式庫。
- 不支援 View Transition 的瀏覽器獲得即時切換（優雅降級）。
- 設定 `prefers-reduced-motion: reduce` 的使用者不播放動畫。

使用 View Transition API，兩個過渡都只需要一個 `document.startViewTransition()` 呼叫，以及在共享元素上設定 `view-transition-name` CSS 屬性。下方的「視覺對比」小節會說明瀏覽器建構的偽元素樹如何運作，而「範例」小節會完整實作這個圖庫。

## 視覺對比

當 view transition 執行時，瀏覽器會在文件上方建立一個暫時的偽元素樹。每個具名元素（加上頁面根元素，預設命名為 `root`）都會取得自己的分支：

```
::view-transition
  ::view-transition-group(root)
    ::view-transition-image-pair(root)
      ::view-transition-old(root)
      ::view-transition-new(root)
  ::view-transition-group(hero-photo)
    ::view-transition-image-pair(hero-photo)
      ::view-transition-old(hero-photo)
      ::view-transition-new(hero-photo)
```

`::view-transition` 是位於所有文件內容上方的全頁覆蓋層，過渡完成後會被移除。

`::view-transition-group(name)` 是定位在 "before" 邊界的包裝元素，會動畫到 "after" 邊界。這正是共享元素產生位置與尺寸變形的原因：群組本身會在兩個邊界框之間平移與縮放。

`::view-transition-image-pair(name)` 包含兩張快照圖像，並處理它們之間的交叉淡入淡出。

`::view-transition-old(name)` 是 before 快照圖像，預設淡出。

`::view-transition-new(name)` 是 after 快照圖像，預設淡入。

若要自訂動畫，可用 `@keyframes` 針對這些偽元素：

```css
@keyframes slide-out-left {
  to { transform: translateX(-100%); opacity: 0; }
}
@keyframes slide-in-right {
  from { transform: translateX(100%); opacity: 0; }
}

::view-transition-old(root) {
  animation: slide-out-left 0.35s ease-in forwards;
}
::view-transition-new(root) {
  animation: slide-in-right 0.35s ease-out forwards;
}
```

## 範例

一個相片集 SPA，點擊縮圖時使用共享元素變形動畫過渡到全尺寸主角視圖。

```html
<div class="gallery" id="gallery">
  <img class="thumb" src="photo-1.jpg" alt="Photo 1" onclick="showDetail(this)">
  <img class="thumb" src="photo-2.jpg" alt="Photo 2"
       onclick="showDetail(this)">
  <img class="thumb" src="photo-3.jpg" alt="Photo 3"
       onclick="showDetail(this)">
</div>
<div class="detail" id="detail" hidden>
  <img class="hero" id="hero-img" src="photo-1.jpg" alt=""
       style="view-transition-name: hero-photo">
  <button onclick="closeDetail()">返回圖庫</button>
</div>
```

注意：只有當前點擊的縮圖和主角圖片共享 `hero-photo` 過渡名稱。在任何時刻只有其中一個是可見的，確保不會發生名稱衝突。

```css
.thumb {
  width: 150px;
  aspect-ratio: 1;
  object-fit: cover;
  cursor: pointer;
  border-radius: 4px;
}

.hero {
  width: 100%;
  max-width: 600px;
  aspect-ratio: 4 / 3;
  object-fit: cover;
  border-radius: 8px;
  display: block;
  margin: 0 auto;
}

/* 縮圖的長寬比是 1:1，主角圖片是 4:3。預設的快照尺寸設定
   （inline-size: 100%; block-size: auto）會讓每張快照各自維持原本的長寬比，
   因此群組在方形與 4:3 方框之間補間時，快照會溢出或在群組內產生黑邊，
   形成可見的邊框不吻合；相片本身並未變形。改用 height: 100%; width: auto
   可讓每張快照配合群組的區塊尺寸，並在行內軸方向覆蓋整個範圍；
   對群組套用 clip 即可隱藏因此產生的行內軸溢出。 */
::view-transition-old(hero-photo),
::view-transition-new(hero-photo) {
  height: 100%;
  width: auto;
}
::view-transition-group(hero-photo) {
  overflow: clip;
}

/* 自定義根部過渡持續時間 */
::view-transition-old(root),
::view-transition-new(root) {
  animation-duration: 0.4s;
}

/* 為偏好減少動態效果的使用者停用所有 view transition */
@media (prefers-reduced-motion: reduce) {
  ::view-transition-old(*),
  ::view-transition-new(*),
  ::view-transition-group(*) {
    animation: none;
  }
}
```

```js
function showDetail(thumb) {
  // 優雅降級：不支援的瀏覽器即時切換
  if (!document.startViewTransition) {
    document.getElementById('gallery').hidden = true;
    document.getElementById('detail').hidden = false;
    return;
  }

  // 過渡前：將 view-transition-name 指派給被點擊的縮圖，
  // 使其參與共享元素變形
  thumb.style.viewTransitionName = 'hero-photo';

  document.startViewTransition(() => {
    // DOM 變更放在回呼內
    document.getElementById('gallery').hidden = true;
    document.getElementById('detail').hidden = false;

    // 更新主角圖片來源以符合被點擊的縮圖
    document.getElementById('hero-img').src = thumb.src;
    document.getElementById('hero-img').alt = thumb.alt;
  });

  // 過渡開始後，從縮圖移除名稱，
  // 以免圖庫再次顯示時產生衝突
  thumb.style.viewTransitionName = '';
}

function closeDetail() {
  if (!document.startViewTransition) {
    document.getElementById('detail').hidden = true;
    document.getElementById('gallery').hidden = false;
    return;
  }

  document.startViewTransition(() => {
    document.getElementById('detail').hidden = true;
    document.getElementById('gallery').hidden = false;
  });
}
```

### 變形的運作方式

呼叫 `showDetail()` 時：

1. 瀏覽器擷取 `hero-photo` 的 "before" 快照（縮圖在其小尺寸位置）以及 `root`（完整頁面）。
2. 回呼執行：圖庫被隱藏，詳細視圖被顯示，主角圖片來源被更新。
3. 瀏覽器擷取 `hero-photo` 的 "after" 快照（主角圖片在其大尺寸位置）以及 `root`。
4. `::view-transition-group(hero-photo)` 將其位置和尺寸從縮圖邊界動畫到主角圖片邊界。
5. 在群組內，`::view-transition-old(hero-photo)`（縮圖快照）交叉淡入淡出到 `::view-transition-new(hero-photo)`（主角快照）。
6. 同時，`::view-transition-old(root)`（圖庫）淡出，`::view-transition-new(root)`（詳細視圖）淡入。

因為縮圖是正方形而主角圖片是 4:3，步驟 4 和步驟 5 補間的是長寬比不同的方框。前面的 CSS 註解說明了原因：若不加上 `height: 100%; width: auto` 覆寫，快照會維持自己的長寬比，並在補間的方框中溢出或產生黑邊，因此需要在群組上加上 `overflow: clip` 來隱藏容納不下的部分。

### 自定義主角變形動畫

預設情況下，變形是交叉淡入淡出加上尺寸/位置插值。若要讓圖片立即呈現完全不透明（只顯示尺寸/位置補間而無不透明度變化）：

```css
::view-transition-old(hero-photo) {
  animation: none;
  opacity: 0; /* 立即隱藏舊快照 */
}
::view-transition-new(hero-photo) {
  animation: none;
  opacity: 1; /* 立即顯示新快照 */
}
```

套用這些規則後，`::view-transition-group(hero-photo)` 仍會動畫化位置與尺寸，但內部圖片不會淡入淡出：它從第一幀就顯示新的全尺寸圖片，並將其從主角尺寸縮放到縮圖尺寸，呈現出沒有交叉淡入淡出的縮放效果。

### 非對稱進出場

用於基於滑動的頁面過渡（從右側進入，向左側退出）：

```css
@keyframes slide-from-right {
  from {
    transform: translateX(30px);
    opacity: 0;
  }
}

@keyframes slide-to-left {
  to {
    transform: translateX(-30px);
    opacity: 0;
  }
}

::view-transition-old(root) {
  animation: slide-to-left 0.3s ease-in forwards;
}

::view-transition-new(root) {
  animation: slide-from-right 0.3s ease-out forwards;
}

@media (prefers-reduced-motion: reduce) {
  ::view-transition-old(*),
  ::view-transition-new(*),
  ::view-transition-group(*) {
    animation: none;
  }
}
```

### 使用 ViewTransition Promise API

`document.startViewTransition()` 返回一個帶有三個 Promise 的 `ViewTransition` 物件：

```js
const transition = document.startViewTransition(() => updateDOM());

// DOM 更新完成且快照已取得時解析
transition.updateCallbackDone.then(() => {
  console.log('DOM 已更新');
});

// 偽元素建立完成且動畫即將開始時解析
// 使用此 Promise 以程式方式取消或跳過動畫
transition.ready.then(() => {
  console.log('動畫開始');
});

// 過渡動畫完成且偽元素被移除時解析
transition.finished.then(() => {
  console.log('過渡完成');
});
```

`ready` Promise 特別適合用來在偽元素上觸發 Web Animations API 動畫，例如沿路徑產生動畫，或使用純 CSS 無法表達的彈簧物理模型。

## 最佳實踐

- MUST 將所有 DOM 變更放在 `startViewTransition` 回呼內。呼叫之前或之後所做的變更，不會被 before/after 快照機制擷取。瀏覽器在回呼執行前立即取得 "before" 快照，在回呼返回的 Promise 解析後取得 "after" 快照；在此期間之外進行的任何 DOM 變更，對過渡系統而言都是不可見的。

- SHOULD 為每個共享元素賦予唯一的 `view-transition-name`。此屬性會指示瀏覽器將元素視為具名快照參與者：它會為該元素擷取獨立的 before/after 快照組，並將其獨立於根部交叉淡入淡出進行變形。若兩個同時可見的元素最終共享相同的 `view-transition-name`，瀏覽器會中止整個過渡，並以 `InvalidStateError` 拒絕 `ViewTransition.ready` Promise；回呼內的 DOM 更新仍會執行，但會變成沒有動畫的即時切換。名稱在快照時所有可見元素中必須是唯一的。一個常見錯誤是對列表中的每個項目套用相同的名稱；開發階段可以攔截 `ready` 的拒絕以及早發現這個問題，並只將名稱指派給參與當前過渡的特定元素。

- SHOULD 始終使用 `@media (prefers-reduced-motion: reduce)` 進行測試，並為請求過的使用者停用或縮減過渡。瀏覽器的預設交叉淡入淡出很細膩，有些開發者因此跳過這個步驟，但套用在 `::view-transition-old` 和 `::view-transition-new` 上的自定義 keyframe 動畫可能足夠劇烈到引發前庭症狀。建議模式如下：

  ```css
  @media (prefers-reduced-motion: reduce) {
    ::view-transition-old(*),
    ::view-transition-new(*),
    ::view-transition-group(*) {
      animation: none;
    }
  }
  ```

- SHOULD 始終提供功能偵測備援方案。`document.startViewTransition` 在不支援 API 的瀏覽器上是 undefined。在呼叫之前進行檢查：

  ```js
  if (!document.startViewTransition) {
    updateDOM(); // 即時切換，無過渡
    return;
  }
  document.startViewTransition(() => updateDOM());
  ```

- MAY 在共享元素上使用 `contain: layout` 以防止佈局副作用。命名的 view-transition 元素在過渡期間被提升到自己的合成層；套用 `contain: layout` 可防止它在移動或縮放時影響周圍元素的佈局。

- MAY 獨立自定義 `::view-transition-old` 和 `::view-transition-new` 以建立非對稱的進出場動畫。例如，離場內容可以淡出並向上滑動，而進場內容則從下方淡入，並對每個偽元素使用不同的 `@keyframes`。

- SHOULD NOT 一次動態地將 `view-transition-name` 指派給許多元素。每個命名元素都會使瀏覽器多擷取一次 GPU 紋理快照，因此為長列表中的每個項目命名會提高擷取成本，並可能明顯延遲過渡開始的時間。請只將名稱指派給參與當前過渡的那一個元素，並在之後移除。若真的需要讓許多元素以群組方式一起動畫，可改用 `view-transition-class`（Chrome 125+、Firefox 144+、Safari 18.2+）：為每個元素保留各自唯一的 `view-transition-name`，但共用同一個 class，再用單一規則 `::view-transition-group(*.your-class)` 進行選取，取代為每個元素分別寫一條選取器。

## 設計思維

### 為什麼 JavaScript 協調的過渡很脆弱

根本問題是 JavaScript 沒有「立即擷取當前繪製截圖」的鉤子。最接近的近似是 `html2canvas` 或在前後使用 `element.getBoundingClientRect()`，但兩者都無法擷取實際的像素內容。即使截圖是可能的，「擷取截圖」、「啟動動畫」、「切換 DOM」和「開始進場動畫」之間的時機也必須透過 `requestAnimationFrame`、`setTimeout` 或 `transitionend` 事件協調。這些交接環節都會引入時機差距，讓半切換狀態有機會閃爍給使用者看到。

GSAP Flip 解決了部分問題：它會記錄 DOM 更新前後的元素位置，並自動計算 CSS transform 差值。但 GSAP Flip 仍需要開發者在 GSAP 管理的回呼中手動觸發 DOM 變更，而且它是用 CSS transform 為即時元素做動畫；它不會擷取合成後的像素快照，因此元素內容在動畫期間仍是即時的（未凍結）。若元素內容在過渡期間發生變化，動畫會從第 0 幀就顯示新內容，因為沒有凍結的快照可以用來動畫過渡。

### 瀏覽器的快照模型如何消除競態

`document.startViewTransition(callback)` 提供了有保證的排序契約：

1. 瀏覽器暫停渲染。
2. 它擷取所有命名元素和根部的當前繪製作為 "before" 快照。
3. 它呼叫回呼並等待其返回的 Promise 解析。
4. 它擷取回呼後的繪製作為 "after" 快照。
5. 它恢復渲染並開始在快照之間播放動畫。

因為瀏覽器控制步驟 2 和步驟 4，快照保證彼此一致。「擷取截圖」與「切換 DOM」之間不存在競態條件：渲染管線會將兩者視為單一的原子操作。

快照是真正渲染到紋理上的合成像素擷取，而不是指向即時 DOM 的參照。在動畫期間，`::view-transition-old(name)` 是元素先前外觀的凍結圖像，`::view-transition-new(name)` 是之後外觀的凍結圖像。若底層 DOM 在動畫進行中再次變更，兩者都不會更新，因為每一個都是靜態圖像，而非元素。

### 第一層級與第二層級的差異

View Transition API 分為兩個層級：

**第一層級**涵蓋同文件過渡：由單一頁面內 JavaScript 觸發的過渡。入口點是 `document.startViewTransition()`，這是一個 JavaScript API。第一層級就是本文所涵蓋的內容，且需要開發者明確呼叫 `startViewTransition` 並將 DOM 變更放在回呼中。

**第二層級**涵蓋跨文件過渡：在多頁應用程式（MPA）中不同頁面 URL 之間的過渡，瀏覽器會導航到新文件。這完全不需要 JavaScript：瀏覽器偵測到 `@view-transition { navigation: auto; }` CSS 規則，並自動將導航包裝在快照機制中。第二層級在 FEE-11104 中說明。

### 為什麼預設是交叉淡入淡出

使用者代理樣式表（UA stylesheet）將預設過渡時長設為 250ms（`animation-duration: 0.25s`），以整個頁面根部的不透明度交叉淡入淡出呈現；這個數值來自 CSS View Transitions Level 1 的使用者代理樣式表，並非個別瀏覽器自訂的慣例。這個選擇是有意為之的：交叉淡入淡出在任意兩個狀態之間都能運作，不需要了解版面配置，也不需要對方向做出假設。更具體的過渡（滑動、變形、揭示）則需要開發者透過命名元素與自訂 keyframe 來表達意圖。

### 框架整合與新的基礎機制

有兩項延伸建構在上述原生 API 之上。`startViewTransition({update, types})` 接受一個 `types` 陣列；搭配 `:active-view-transition-type()` CSS 偽類別，可以讓同一份樣式表依照過渡類型分支動畫效果，例如區分 `forwards`（前進）與 `backwards`（後退）兩種情境，而不需要額外撰寫 JavaScript 分支邏輯。React 在 Canary 通道中提供了實驗性的 `<ViewTransition>` 元件，它包裝了 `startViewTransition` 並將其與 React 的渲染週期協調，讓共用同一個 `name` prop 的卸載中與掛載中 `<ViewTransition>` 能跨不同元件樹連接起來。這兩項延伸都不會取代本文描述的機制：兩者最終都會編譯為同一個 `document.startViewTransition()` 呼叫與同一套偽元素樹。

## 瀏覽器支援

| 瀏覽器  | 同文件 View Transitions | 備註 |
|---------|------------------------|------|
| Chrome  | 111                    | 首個實作 |
| Edge    | 111                    | 基於 Chromium |
| Firefox | 144                    | Firefox 144 推出 |
| Safari  | 18                     | iOS Safari 18 亦支援 |

功能偵測：

```js
if (document.startViewTransition) {
  // 支援 View Transitions 第一層級
}
```

或透過 CSS（主要用於跨文件第二層級，但也可用於文件同文件支援的功能查詢）：

```css
@supports (view-transition-name: none) {
  /* 支援 View Transitions */
}
```

漸進增強模式：始終為不支援的瀏覽器提供即時切換備援，並為偏好減少動態效果的使用者停用動畫。這兩項檢查彼此獨立，應同時存在。

同文件 view transitions 在 2025 年成為 Baseline Newly Available，意味著三大主要瀏覽器引擎都已支援。跨文件（第二層級）過渡的支援範圍較窄：截至 2026 年中，Chrome 與 Edge 126+ 以及 Safari 18.2+ 已支援，Firefox 則尚未推出支援。完整比較請見 FEE-11104。
