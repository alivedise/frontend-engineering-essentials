# [FEE-11102] calc-size() & interpolate-size — 讓 auto 可動畫化

:::info
透過關鍵字尺寸插值的選用設定，讓 `height: 0` → `height: auto` 的 CSS 過渡動畫成真，不需要 JavaScript、`max-height` 技巧，也不會產生緩動曲線失真。
:::

:::warning Limited Availability
目前僅支援 Chrome 129+/Edge 129+。Firefox 與 Safari 的支援仍在開發中。
正式上線前請先確認 MDN 相容性表格。
:::

## 背景

CSS 過渡動畫需要兩個數值端點才能進行插值。`height: 0` 到 `height: 200px` 運作完美：兩者都是樣式計算階段就能解析的像素值，瀏覽器可以計算每個中間點。問題出在 `auto`。

`auto` 是佈局關鍵字。它的解析依賴元素的內容、容器區塊，以及彈性或格線脈絡。這些因素要到樣式計算之後的佈局階段才會確定。當瀏覽器在插值步驟詢問「`height: auto` 的數值是多少？」時，佈局尚未執行，答案是：未知。沒有數值，就無法插值，過渡動畫因此跳過，直接跳至最終狀態。

手風琴選單、展開元件、抽屜面板和可展開的卡片，都自然而然地需要從折疊高度 `0` 動畫到「內容所需的高度」。缺乏原生支援時，開發者只能在三種不完美的變通方式中選擇。

**`max-height` 技巧**：將 `max-height` 從 `0` 過渡到像 `9999px` 這樣的大哨兵值。這有兩個根本性問題：緩動曲線是套用在 `0px → 9999px` 的完整範圍上，而非實際的 `0px → 內容高度` 範圍，因此元素會在動畫時間軸的前段就衝到最終位置，之後靜止不動直到動畫結束。時間感完全錯誤，且因內容長度不同而有所差異。

**JavaScript `scrollHeight` 方式**：展開時，讀取 `element.scrollHeight`（在佈局後返回實際像素高度），將其指定給 `element.style.height`，等待 `transitionend`，再還原為 `height: auto`。這能正確運作，但需要事件監聽器、命令式 DOM 操作，以及每次展開/折疊時的強制佈局讀取。

**`visibility: hidden` 變通方式**：使用 `visibility: hidden` 而非 `height: 0` 讓元素保持在佈局流中。避免了缺少快照的問題，但強制「隱藏」元素仍佔用空間，這通常不是期望的行為。

Chrome 129 在語言層面解決了這個問題，推出了兩個新的 CSS 功能：

- **`interpolate-size: allow-keywords`**：一個 CSS 屬性，讓元素（或透過 `:root` 讓整份文件）選用關鍵字尺寸插值。設定後，`height: auto` 就能像數值一樣參與 CSS 過渡和動畫。
- **`calc-size()`**：一個新的 CSS 函式，接受內縮尺寸關鍵字（`auto`、`min-content`、`max-content`、`fit-content`）以及一個使用 `size`（解析值）的運算式，能對關鍵字尺寸進行算術運算，同時也隱式為所使用的特定屬性啟用關鍵字插值。

你正在建立一個常見問題頁面，使用手風琴元件。每個問題展開以顯示答案。設計要求高度平滑過渡：真實地從 `0` 展開到自然內容高度，而非淡入淡出或 `max-height` 近似效果。由於每個答案的內容長度不同，硬編碼的像素值並不可行。

需求如下：

- 展開：`height: 0` → `height: auto`，0.3 秒緩動曲線平滑動畫。
- 折疊：反向動畫。
- 純 CSS 動畫：不需要 JavaScript 測量高度。
- 不支援的瀏覽器（Firefox、Safari）使用 `max-height` 備援方案。
- 若內容高度變化（例如圖片非同步載入）也不會產生佈局異常。

只需在 `:root` 設定 `interpolate-size: allow-keywords`，並在面板上設定 `height` 過渡，手風琴動畫就能濃縮為兩個 CSS 宣告。

## 最佳實踐

- SHOULD 在 `:root` 設定 `interpolate-size: allow-keywords` 作為漸進增強。因為此屬性會繼承，設定在 `:root` 即可為整份文件啟用關鍵字尺寸過渡。在不支援此屬性的瀏覽器中，宣告會被靜默忽略。沒有視覺差異或佈局副作用。在 Chrome 129+ 中，它會全域解鎖 `auto` 動畫。

- MUST 為不支援的瀏覽器提供備援方案。使用 `@supports (interpolate-size: allow-keywords)` 包覆 `height` 過渡，並在 `@supports not` 區塊內提供 `max-height` 過渡。這確保 Firefox 和 Safari 的使用者仍能獲得功能性的動畫（即使不完美），而極舊版本瀏覽器的使用者也能看到即時的顯示/隱藏而不產生佈局錯誤。

- SHOULD 在需要對 `auto` 進行算術運算時使用 `calc-size(auto, size)`。例如，若面板有 `16px` 的垂直內距需要納入動畫高度，可以寫 `height: calc-size(auto, size + 32px)`，而非分拆多個過渡。`calc-size()` 中的 `size` 識別符解析為關鍵字的像素值（自然內容高度）。任何有效的 `<calc-sum>` 運算式都可使用。

- SHOULD NOT 對同一個元素混用 `calc-size()` 和 `interpolate-size` 解決相同問題：它們是互補的工具。`interpolate-size: allow-keywords` 是套用在元素上的策略，影響所有關鍵字值過渡；`calc-size()` 是特定宣告的點對點值，只對該屬性隱式啟用插值。建議在 `:root` 全域啟用 `interpolate-size: allow-keywords`，只有在需要對解析尺寸進行算術運算時才使用 `calc-size()`。

- SHOULD NOT 在未測試 Firefox 和 Safari 的情況下，將 `interpolate-size` 用於佈局關鍵的互動元件。這兩款瀏覽器尚未支援。將其作為能正常運作的基礎實作之上的增強層。

- MAY 在 `@keyframes` 動畫中使用 `interpolate-size: allow-keywords`，不僅限於 `transition`。此屬性對兩者都有效。當 `interpolate-size: allow-keywords` 在作用範圍內時，`from { height: 0 } to { height: auto }` 的關鍵幀動畫可以正確播放。

- MAY 對 `auto` 以外的關鍵字使用 `calc-size()`：`min-content`、`max-content` 和 `fit-content` 都是有效的。例如，`calc-size(max-content, size * 0.75)` 會產生元素最大內縮寬度的 75%。

## 設計思維

### 為什麼 `auto` 無法動畫化

CSS 過渡透過捕捉兩個計算樣式快照來運作：一個在觸發變化之前，一個在之後。瀏覽器在指定的持續時間內插值這兩個快照。

關鍵詞是「計算」。樣式計算解析關鍵字、執行層疊和繼承、計算屬性值，但不執行佈局。`auto` 在佈局時解析，而佈局發生在樣式計算之後。當瀏覽器的過渡機制在樣式計算階段詢問「`height: auto` 的數值是多少？」時，佈局尚未執行，答案是：未知。沒有數值，就無法插值，過渡動畫因此被跳過。

這是 CSS 處理模型的必然結果，並非瀏覽器的錯誤或疏忽。樣式計算和佈局是不同的階段，而過渡系統運作在樣式計算階段。

### `max-height` 如何運作，以及為什麼它是錯的

`max-height` 技巧透過將無法回答的問題（「`auto` 是多少？」）替換成可以回答的問題（「`9999px` 是多少？」）來規避問題。從 `max-height: 0` 過渡到 `max-height: 9999px` 給瀏覽器兩個已知數字。

問題在於緩動函式（無論是 `ease`、`ease-in-out` 還是自訂三次貝茲曲線）是套用在過渡的完整數值範圍上，即 `0` 到 `9999`（或使用的任何哨兵值）。若實際內容高度是 `200px`，那麼過渡的 97.9% 數值範圍是未使用的。元素在動畫時間軸的前 2% 就已到達自然高度。之後瀏覽器繼續將 `max-height` 從 `200px` 插值到 `9999px`，但元素的渲染高度已在 `200px`，無法進一步增長。結果是瞬間跳到位置，接著是一段漫長的隱形動畫，使緩動感完全錯誤。

使用較小的哨兵值（如 `500px`）可以減少失真，但需要知道內容高度的大致上限，這讓使用 `auto` 的意義大打折扣。

### JavaScript `scrollHeight` 方式如何運作

`element.scrollHeight` 返回元素的完整渲染高度（包含溢位部分），實際上就是 `height: auto` 會產生的像素等效值。佈局後讀取它可以得到 `auto` 會產生的解析數值。

展開時的步驟：

1. 將 `height` 從 `0` 設定為 `scrollHeight` 值。這是一個端點為已知數值的 `0px → Npx` 過渡，能以正確的緩動動畫化。
2. 監聽 `transitionend`。觸發時，還原 `height: auto`，使元素能在內容變化時（例如延遲載入的圖片）自由重排。

折疊時的步驟則相反：讀取 `scrollHeight`，將其設定為起始 `height`，觸發重排以登記該值，然後設定 `height: 0` 開始過渡。

這能正確運作，但每次使用者互動時都強制進行佈局讀取（`scrollHeight`）。佈局讀取是同步的，可能觸發重排，在複雜頁面上代價高昂。事件監聽器也增加了 CSS 本不應該需要的命令式連結。

### 為什麼 `interpolate-size` 更好

`interpolate-size: allow-keywords` 指示瀏覽器的樣式引擎在插值步驟執行之前先解析 `auto` 等內縮關鍵字。瀏覽器執行推測性佈局以找出解析值，然後將該像素值用作插值端點。

結果是一個語義上等同於 JS 方式的過渡，但在平台層面實作：緩動是套用在正確範圍上（`0px` 到實際內容高度），時間感準確，且不需要 JavaScript。解析值也是動態的：若內容在兩次過渡之間發生變化，下一次過渡會自動使用更新後的解析值。

`calc-size()` 進一步允許將解析值用於算術運算式。`calc-size(auto, size + 2rem)` 先解析 `auto`，再對結果加上 `2rem`。這無法單獨用 `interpolate-size` 表達，後者只能啟用關鍵字作為端點，無法修改解析值。

## 範例

一個手風琴元件，每個面板使用 `interpolate-size: allow-keywords` 從 `height: 0` 展開到 `height: auto`，並為不支援的瀏覽器提供 `max-height` 備援方案。

```html
<div class="accordion">
  <button class="accordion__trigger" aria-expanded="false"
          onclick="this.setAttribute('aria-expanded',
            this.getAttribute('aria-expanded') === 'true' ? 'false' : 'true')">
    什麼是 CSS？
  </button>
  <div class="accordion__panel">
    <p>CSS（層疊樣式表）是一種樣式表語言，用於描述以 HTML 或 XML 撰寫的文件的呈現方式。</p>
  </div>
</div>
```

```css
/* 基礎：面板為折疊狀態 */
.accordion__panel {
  height: 0;
  overflow: hidden;
}

/* 漸進增強：支援 interpolate-size 的瀏覽器獲得平滑高度動畫 */
@supports (interpolate-size: allow-keywords) {
  :root { interpolate-size: allow-keywords; }
  .accordion__panel { transition: height 0.3s ease; }
  .accordion__trigger[aria-expanded="true"] + .accordion__panel {
    height: auto;
  }
}

/* 備援：不支援 interpolate-size 的瀏覽器改用 max-height 動畫 */
@supports not (interpolate-size: allow-keywords) {
  .accordion__panel { max-height: 0; transition: max-height 0.3s ease; }
  .accordion__trigger[aria-expanded="true"] + .accordion__panel {
    max-height: 500px; /* 設定足夠高以涵蓋內容 */
  }
}
```

### 展開的運作方式

當觸發器被點擊且 `aria-expanded` 變為 `"true"` 時：

1. 選擇器 `.accordion__trigger[aria-expanded="true"] + .accordion__panel` 匹配，將面板的 `height` 從 `0` 改為 `auto`。
2. 由於 `:root` 設有 `interpolate-size: allow-keywords`，瀏覽器在計算過渡中間點之前推測性地解析 `auto`。
3. `height` 過渡從 `0px` 動畫到 `auto` 的解析像素值，緩動套用在確切範圍上。
4. 面板平滑地展開至自然內容高度。

折疊時，屬性返回 `"false"`，選擇器不再匹配，`height` 恢復為 `0`，過渡反向播放。

### 使用 `calc-size()` 處理含內距的高度

若面板有垂直內距（`padding-block: 1rem`）需要納入動畫高度，使用 `calc-size()` 將內距加到解析後的 auto 值上：

```css
.accordion__trigger[aria-expanded="true"] + .accordion__panel {
  /* 動畫到內容高度 + 2rem（上下內距） */
  height: calc-size(auto, size + 2rem);
}
```

`size` 識別符解析為裸 `auto` 會解析到的相同像素值。加法運算產生一個含內距的目標高度。這等同於 JS 模式中讀取 `scrollHeight` 並加上 `paddingTop + paddingBottom`，但完全是宣告式的。

### 搭配 `max-content` 使用 `calc-size()`

`calc-size()` 支援任何內縮尺寸關鍵字。若要將元素限制在其自然最大寬度的 75% 並仍能正確動畫：

```css
.panel {
  width: calc-size(max-content, size * 0.75);
  transition: width 0.3s ease;
}
```

`calc-size(max-content, ...)` 中的 `size` 識別符解析為元素的 `max-content` 寬度。乘以 `0.75` 產生最大自然寬度 75% 的寬度值。過渡到和從此值的動畫都能正確運作，因為 `calc-size()` 為該屬性隱式啟用了關鍵字插值。

### 減少動態效果

將僅動畫相關的規則包覆在 `@media (prefers-reduced-motion: no-preference)` 中，使請求了減少動態效果的使用者看到即時的顯示/隱藏而非過渡：

```css
/* 基礎：面板為折疊狀態 */
.accordion__panel {
  height: 0;
  overflow: hidden;
}

/* 漸進增強：支援 interpolate-size 的瀏覽器獲得平滑高度動畫 */
@supports (interpolate-size: allow-keywords) {
  :root { interpolate-size: allow-keywords; }

  @media (prefers-reduced-motion: no-preference) {
    .accordion__panel { transition: height 0.3s ease; }
  }

  .accordion__trigger[aria-expanded="true"] + .accordion__panel {
    height: auto;
  }
}

/* 備援：不支援 interpolate-size 的瀏覽器改用 max-height 動畫 */
@supports not (interpolate-size: allow-keywords) {
  @media (prefers-reduced-motion: no-preference) {
    .accordion__panel { max-height: 0; transition: max-height 0.3s ease; }
    .accordion__trigger[aria-expanded="true"] + .accordion__panel {
      max-height: 500px;
    }
  }
}
```

這種分層確保：

- Chrome 129+，允許動態效果：平滑的 `height: auto` 過渡。
- Chrome 129+，減少動態效果：即時展開/折疊。
- Firefox/Safari，允許動態效果：`max-height` 近似動畫。
- Firefox/Safari，減少動態效果：即時展開/折疊。

## 深入探討

### `interpolate-size` 的繼承與作用範圍

`interpolate-size` 是繼承屬性。在 `:root` 設定後，文件中每個元素都會啟用關鍵字尺寸過渡。這是刻意的設計：建議模式是在 `:root` 設定並讓它向下繼承。

也可以設定在特定容器以縮小作用範圍：

```css
.expandable-section {
  interpolate-size: allow-keywords;
}
```

只有 `.expandable-section` 內的元素才會啟用關鍵字插值，文件其餘部分不受影響。在逐步推出時若想審計或限制行為的範圍，這很有用。

預設值是 `interpolate-size: numeric-only`，保留了 Chrome 129 之前的行為。在 `:root` 選用不會改變任何在兩個數值之間過渡的現有動畫。這些不受影響。只有一端或兩端涉及內縮關鍵字的過渡才會改變。

### `calc-size()` 與隱式插值選用

當屬性值包含 `calc-size()` 時，瀏覽器會為該宣告隱式啟用關鍵字插值，即使元素未設定 `interpolate-size`。這意味著 `calc-size()` 是自包含的：不需要在 `:root` 設定 `interpolate-size: allow-keywords` 就能使用它。

```css
/* 無需在 :root 設定 interpolate-size: allow-keywords 即可運作 */
.panel {
  height: calc-size(auto, size);
  transition: height 0.3s ease;
}
.panel.collapsed {
  height: 0;
}
```

`calc-size(auto, size)` 不做任何修改，等同於 `auto` 但啟用了插值。在不想全域啟用關鍵字插值時，可作為有針對性的選用方式。

### 推測性佈局與效能

當瀏覽器需要解析 `auto` 作為插值端點時，它會執行推測性佈局，以確定元素的高度會是多少。這比解析靜態像素值需要更多工作，但比完整的文件重排少。

實際上，代價與在 JavaScript 中讀取 `scrollHeight` 相當：兩者都需要佈局。CSS 方式的優勢在於它整合於瀏覽器的渲染管線，而非由 JavaScript 觸發，允許瀏覽器更有效地排程和批次處理。

對於有許多同時進行的關鍵字尺寸過渡的大型或複雜文件，可能會觀察到佈局壓力。在假設這是瓶頸之前，請先進行效能分析。

### `@keyframes` 與 `interpolate-size`

`interpolate-size: allow-keywords` 同樣適用於 `@keyframes` 動畫，不限於 `transition`。當屬性在作用範圍內時，含關鍵字值的關鍵幀動畫能正確播放：

```css
@keyframes expand {
  from { height: 0; }
  to   { height: auto; }
}

.panel {
  animation: expand 0.3s ease forwards;
}
```

在 `:root`（或 `.panel` 元素）設定 `interpolate-size: allow-keywords` 後，此動畫能正確播放。若未設定，瀏覽器在第一幀就會跳至 `height: auto`。

### 與 `overflow` 的互動

動畫化 `height: 0` 到 `height: auto` 時，內容在 `height: 0` 時必須隱藏。在元素上設定 `overflow: hidden` 以在過渡期間裁切內容。過渡完成後，`height: auto` 允許元素自由增長，但 `overflow: hidden` 仍然存在，會裁切任何溢位內容。若展開狀態應允許溢位（例如，裡面有可見的工具提示的下拉選單），可在過渡結束後將 `overflow` 改為 `visible`，或使用更符合 CSS 原生做法的 `overflow: clip` 搭配 `clip-path`。

```css
.accordion__panel {
  height: 0;
  overflow: hidden;
  transition: height 0.3s ease;
}

/* 動畫完成後透過延遲過渡顯示溢位 */
.accordion__trigger[aria-expanded="true"] + .accordion__panel {
  height: auto;
  overflow: visible;
  /* 延遲 overflow 變化直到 height 過渡完成 */
  transition: height 0.3s ease, overflow 0s 0.3s;
}
```

## 瀏覽器支援

| 瀏覽器  | `interpolate-size` | `calc-size()` | 備注 |
|---------|-------------------|---------------|------|
| Chrome  | 129               | 129           | |
| Edge    | 129               | 129           | 基於 Chromium |
| Firefox | 未支援            | 未支援        | 開發中 |
| Safari  | 未支援            | 未支援        | 開發中 |

漸進增強檢測：

```css
@supports (interpolate-size: allow-keywords) {
  :root { interpolate-size: allow-keywords; }
  /* 啟用關鍵字尺寸過渡 */
}

@supports not (interpolate-size: allow-keywords) {
  /* max-height 備援方案 */
}
```

或透過 JavaScript：

```js
const supported = CSS.supports('interpolate-size', 'allow-keywords');
```

由於 `calc-size()` 是值層級的功能，無法直接用 `CSS.supports()` 檢測。使用 `interpolate-size` 屬性檢測作為代理：兩個功能都在 Chrome 129 一起推出，在其他瀏覽器中也會一起推出。

Firefox 已有開放的實作工單並表達了推出意圖。Safari 的 WebKit 團隊已將 `interpolate-size` 標記為追蹤中的功能。隨著瀏覽器支援演進，請查看下方連結的 MDN 相容性表格以獲取最新狀態。

## 延伸閱讀

- [FEE-11101 @starting-style — 無需 JavaScript 的進場動畫](./11101.md)：這兩個功能都解決了用純 CSS 動畫化顯示狀態變化的問題。`@starting-style` 為進場過渡提供「之前」的快照；`interpolate-size` 為關鍵字值過渡提供解析後的數值端點。它們互相補充，可以結合使用：一個元素可以同時擁有 `@starting-style` 進場動畫和 `height: auto` 展開動畫。
