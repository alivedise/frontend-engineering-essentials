# [FEE-1011] Accessible Name 計算：AccName 演算法如何決定標籤

:::info
螢幕閱讀器遇到一顆按鈕或一個連結時，會唸出一段文字，讓使用者知道這是什麼控制項。這段文字叫 accessible name（無障礙名稱），計算方式由 W3C 的 Accessible Name and Description Computation 規範定義。演算法依固定順序檢查候選來源：先看 `aria-labelledby`，再看 `aria-label`，然後是 HTML 原生標記（`label` 元素、`alt` 屬性這類），接著收集元素內部的文字，最後看 `title` 屬性；第一個非空的結果就是名稱。Chrome DevTools 的 accessibility 面板直接呈現這個計算：它依優先順序列出所有候選來源，並標出勝出的那一個。誤解這個順序會寫出標籤 bug：在按鈕上加了 `aria-label`，螢幕閱讀器就只唸它的值，不再唸按鈕上的可見文字。
:::

## Context

Accessible Name and Description Computation 1.2 是 W3C Working Draft，走 Recommendation 進程，最近一次發布在 2026 年 8 月 5 日，內容更新自 AccName 1.1 Recommendation。演算法的核心結構歷經各版本沒有變：一串固定順序的步驟，第一個非空結果勝出。HTML 這邊的細節由另一份 W3C 規範補完，名叫 HTML Accessibility API Mappings（HTML-AAM）：它規定 `label`、`alt`、`placeholder`、`title` 這些 HTML 標記如何套進 AccName 演算法的「原生標記」那一步。W3C 的 ARIA Authoring Practices Guide（APG）與多家無障礙顧問公司的建議方向一致：優先用可見文字和原生 HTML 標記命名，少用 ARIA 命名屬性。ARIA、表單標籤、螢幕閱讀器這些主題都圍繞著「元素叫什麼名字」；這一篇說明當多個候選標籤同時存在時，瀏覽器怎麼算出螢幕閱讀器實際唸出的那一個。

## Example

這顆儲存按鈕同時帶著三個名稱來源，還有一個 icon font 字元：

```html
<style>
  .icon-save::before {
    font-family: "IconFont";
    content: "\f0c7";
  }
</style>

<button class="icon-save" title="Save the current draft" aria-label="Save">
  Save document
</button>
```

按鈕上沒有 `aria-labelledby`，演算法走到 `aria-label` 那一步就回傳它的值，算出的名稱是 `Save`。在 Chrome DevTools 選取這顆按鈕並打開 accessibility 面板：面板依計算順序列出候選來源，標出 `aria-label` 勝出，沒被選上的候選排在下面。button 屬於「以內容命名」（name from content）的角色：這類角色可以把元素子樹裡的文字收集起來當名稱，`<a>`、`<td>`、`<button>` 都在此列。但 `aria-label` 排在前面，它一勝出，螢幕閱讀器就只唸 `Save`；可見文字 `Save document` 和 icon 字元都不會唸出來。

刪掉 `aria-label` 之後，演算法接著檢查下一個來源：以內容命名。這一步遞迴走訪子樹收集文字，規範還要求瀏覽器把 CSS `::before` 的文字內容接在最前面、`::after` 的接在最後面。算出的名稱變成 private-use 字元 `\f0c7` 加上 `Save document`。按鈕原始碼裡的縮排和換行不會保留：規範把結果正規化成一條扁平字串，carriage return、換行、tab、form feed 都換成單一空格，連續空格再合併成一個。

再把 class 和可見文字也刪掉，只剩 `<button title="Save the current draft"></button>`。前面每個來源都是空的，`title` 那一步回傳它的值，名稱變成 `Save the current draft`。APG 把 `title` 歸類為瀏覽器備援：沒有更強的來源時它才生效，不要把它當成正式的命名手段。

`aria-labelledby` 的路徑對隱藏內容有一條例外規則：

```html
<span id="discard-hint" style="display: none">Discard unsaved changes</span>
<button aria-labelledby="discard-hint">X</button>
```

隱藏節點在名稱計算裡通常只回傳空字串。但這個 `span` 被按鈕的 `aria-labelledby` 指到，例外規則生效：它的內容照樣參與計算，螢幕閱讀器唸這顆按鈕時唸的是 `Discard unsaved changes`。按鈕裡可見的 `X` 沒被採用，因為 `aria-labelledby` 在步驟順序裡排在以內容命名前面。

## Best Practices

- 禁止在「禁止命名」（name prohibited）的角色上用 `aria-label` 或 `aria-labelledby`。對應到日常 HTML，受影響的是這十個元素：`<p>`、`<span>`、`<code>`、`<em>`、`<strong>`、`<del>`、`<ins>`、`<sub>`、`<sup>`、`<caption>`。只要沒有另外指定 `role` 屬性，HTML-AAM 給這十個元素的預設角色（依序是 paragraph、generic、code、emphasis、strong、deletion、insertion、subscript、superscript、caption）全部在 WAI-ARIA 1.2 的禁止命名清單上；清單共 11 種角色，第 11 種是 presentation。這些角色沒有名稱，規範明文禁止作者為它們命名，寫上去的命名屬性不會生效。WAI-ARIA 1.3 草案把清單擴充到 17 種，新增 definition、mark、suggestion、term、time、tooltip。
- 在以內容命名的角色（button、連結這類）上用 `aria-label` 時，必須拿螢幕閱讀器實際聽一次結果：屬性值會取代整個子樹的文字，而且不會顯示在畫面上，光看畫面察覺不到唸出來的內容變了。
- 應該直接用控制項的可見文字當名稱。控制項指使用者操作的元素，像按鈕、連結、表單輸入；可見文字指畫面上實際顯示在控制項裡的文字，以本文範例來說就是按鈕上的 Save document。APG 指出用可見文字當名稱能簡化維護、減少 bug，也降低翻譯需求。
- 應該優先用 `label`、`alt` 這類原生 HTML 標記命名，少用 ARIA 屬性；ARIA 用錯會蓋掉正確的 HTML 語義，ARIA 屬性用得多的頁面錯誤率也偏高。
- 不應該把 `title` 屬性當成主要命名手段；只有前面所有來源都空了它才生效，APG 的基本原則也要求避免依賴這種瀏覽器備援。
- 可以在 Chrome DevTools 的 accessibility 面板驗證算出的名稱；面板依計算順序列出候選來源，並標出勝出者。
- 應該把名稱寫得簡短、有用；APG 把這列為基本原則。
- 可以用 `aria-labelledby` 指向隱藏元素。名稱計算平常跳過隱藏元素（`display: none`、`visibility: hidden`、HTML 的 `hidden` 屬性都算隱藏），把它們算成空字串；但被 `aria-labelledby` 或 `aria-describedby` 指到的隱藏元素例外，它的文字照樣被讀進名稱。運作方式見 Example 最後一段的範例。

## Failure Modes

前面各節說明的是規則本身；這一節整理規則被踩中時的實際 bug 樣態，每一個都能在 DevTools accessibility 面板看到是哪個來源勝出。

**aria-label 蓋掉可見文字。** 畫面上寫 `Save document` 的按鈕，加上 `aria-label="Submit"` 之後，螢幕閱讀器唸的是 `Submit`。出錯的位置在 `aria-label` 那一步：它排在以內容命名前面，值又不顯示在畫面上，所以光看畫面察覺不到唸出來的內容變了。

**螢幕閱讀器照樣唸出 display:none 的標籤。** 重構時把畫面上的標籤 `span` 改成隱藏，卻沒有清掉按鈕上指向它的 `aria-labelledby`，螢幕閱讀器唸的因此一直是舊標籤的文字。出錯的位置在隱藏節點的例外規則（見 Example 最後一段）：被 `aria-labelledby` 指到的節點即使隱藏也參與計算，規範的註記說明這是刻意設計，作者既然明確引用那個隱藏節點，就視為要它參與命名。

**icon font 字元污染名稱。** 以本文 Example 的按鈕為例：拿掉 `aria-label` 之後，`.icon-save::before` 注入的 `\f0c7` 被接在名稱最前面，算出 `\f0c7 Save document`。出錯的位置在以內容命名那一步的 `::before`/`::after` 收集規則；同一個 icon class 套在哪個元素上，這個字元就混進哪個元素的名稱。

**放在禁止命名角色上的名稱不生效。** `<p aria-label="免責聲明">本文僅供參考</p>`：paragraph 屬於禁止命名的角色，這個 `aria-label` 不會變成段落的名稱，螢幕閱讀器不會唸出「免責聲明」。哪些元素預設就在禁止命名的角色上，見 Best Practices 第一條的清單。
