# [FEE-0] FEE Overview

:::info
FEE (Frontend Engineering Essentials) is a collection of vendor-agnostic guidelines and best practices for frontend engineering.
:::

## Context

Frontend engineering spans a vast landscape -- from HTML semantics and CSS layout to component architecture, state management, and build tooling. Engineers often learn these concepts piecemeal, through scattered blog posts, framework-specific tutorials, or painful production debugging. FEE provides a structured, numbered set of principles that build a coherent mental model of frontend engineering.

## Purpose

- Establish shared vocabulary for frontend engineering discussions
- Provide actionable, vendor-neutral guidance for common frontend decisions
- Serve as an onboarding resource for engineers at all levels
- Bridge the gap between "I know the framework" and "I understand the platform"

## How to Read FEEs

Each FEE follows a consistent structure:

- **Context** -- Why this principle matters
- **Scenario** (100–400 series only) — A concrete product situation showing when this API or feature is the right tool.
- **Design Thinking** -- The mental model and reasoning behind the principle
- **Best Practices** -- Actionable rules (MUST / SHOULD / AVOID)
- **Visual** -- Diagrams where they aid understanding
- **Example** -- Concrete, vendor-agnostic examples
- **Common Mistakes** -- Anti-patterns to avoid
- **Related FEEs** -- Cross-references to other principles
- **References** -- External resources for deeper learning

## Article Metadata Fields

Each FEE article's frontmatter carries the following fields:

| Field | Values | Meaning |
|-------|--------|---------|
| `id` | integer | Unique article number within the FEE numbering scheme |
| `title` | string | Human-readable article title |
| `state` | `draft`, `placeholder` | Publication state |
| `overview` | `true` (omitted if false) | Marks category overview pages; these do not have a `level` field |
| `level` | `entry`, `mid`, `senior`, `???` | Intended audience difficulty. `entry` = suitable for juniors; `mid` = assumes solid fundamentals; `senior` = advanced depth. `???` = pending manual review. |
